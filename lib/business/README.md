# lib/business — 법인·사업자 공개 정보 조회 (F-015 AC4, DEC-052)

서류 분석 결과의 당사자 가운데 **법인·상호가 있는 사업자**에 대해 공개된 정보(상호·주소·업종·설립일)를 공식 API로 찾아 보여 준다. 모델을 쓰지 않는다.

| 파일        | 책임                                                                                                                             |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `policy.ts` | 순수 규칙: 요청 검증(`parseLookupRequest`), 응답 줄이기(`parseNaverLocal`·`parseCorpOutline`), 바로 가기 링크, `BUSINESS_NOTICE` |
| `source.ts` | server-only. 공식 API 호출. 키가 없으면 `no_key`, 실패하면 `failed`                                                              |

## 출처

| 출처                                                          | 환경변수                                | 쓰는 항목                            |
| ------------------------------------------------------------- | --------------------------------------- | ------------------------------------ |
| 네이버 지역 검색 API `openapi.naver.com/v1/search/local.json` | `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` | 상호, 분류, 주소, 링크               |
| 공공데이터포털 금융위원회_기업기본정보 `getCorpOutline_V2`    | `DATA_GO_KR_SERVICE_KEY`                | 법인명, 주소, 설립일, 업종, 홈페이지 |

- 네이버 지도 화면은 수집하지 않는다(공식 API만). DART는 회사 고유번호 목록이 있어야 이름으로 찾을 수 있어 링크만 둔다.
- 두 API의 응답 필드 이름은 공개 명세 기준이다. 키를 넣은 뒤 `pnpm test:live`의 `tests/live/business.live.test.ts`(무료)로 확인한다.

## 지키는 것

- **개인을 찾는 기능이 아니다.** 두 출처 모두 상호·법인만 돌려준다. 대표자 이름·법인등록번호·사업자등록번호·전화번호는 응답에서 버린다.
- 찾은 곳이 서류의 당사자와 같은 곳인지 판단하지 않는다. 평판·위험도 같은 판정을 넣지 않는다(절대 규칙 2). 화면은 `BUSINESS_NOTICE`와 "같은 이름의 다른 곳일 수 있다"는 안내를 붙인다.
- 이름은 요청 본문으로만 받고, 연락처·주소·번호가 섞인 이름은 외부로 보내지 않는다. 조회한 이름·결과·키·요청 주소는 저장·로그·응답에 남기지 않는다.
