## 4. 롤백

문제가 생기면 위에서부터 가장 가벼운 방법을 쓴다.

1. **Vercel Instant Rollback** — Vercel 대시보드 → Deployments → 직전 정상 배포의 메뉴 → "Instant Rollback"(또는 "Promote to Production"). 코드는 그대로 두고 배포만 되돌린다. 원인을 고친 뒤 다시 푸시하면 새 배포가 production이 된다.
2. **커밋 되돌리기** — 원인 커밋을 `git revert <커밋>`으로 되돌리고 `main`에 푸시한다. 강제 푸시(`--force`)는 쓰지 않는다.
   - P6 화면만 되돌릴 때: `git revert ee48ede` (P9 테스트 `4bccd57`, P10 정책 커밋도 함께 되돌려야 테스트가 맞는다).
3. **분석 모드** — 화면은 정상인데 분석에서 비용·오류가 의심되면 Vercel에서 `AI_MODE`를 지우고 Redeploy. 무료 모드는 Claude를 부르지 않는다. 유료 분석 버전은 태그 `paid-ai-v1`에 보존돼 있다.
4. **DB** — P6~P11은 마이그레이션을 바꾸지 않았다. DB 롤백은 필요 없다. Supabase 프로젝트가 멈추면(무료 플랜 일시 정지) 대시보드에서 Restore 한 뒤 `pnpm db:push --dry-run` → `pnpm db:push` → `pnpm db:verify`.

## 5. 알려진 제한 (데모)

- 소셜 로그인은 연결 전이다. 3회를 다 쓰면 로그인 안내만 보인다 (Supabase Auth Google 공급자 설정 후 연결).
- 법제처 Open API는 등록된 IP·도메인에서만 응답한다. 배포 주소 등록 전에는 자유 질문이 "지금은 예시 질문으로 체험할 수 있어요"로 안내된다.
- 질문 문장(마스킹본)은 결과 화면 표시용으로 그 브라우저 탭(sessionStorage)에만 있다. 다른 기기·탭에서 결과 주소를 열면 질문 문장 없이 결과만 보인다.
- `POST /inquiries`는 비로그인 3회를 다 썼는지만 보고 IP 상한은 분석(analyze)에만 있다. 분석 없이 질문만 반복 생성하는 남용은 DB 행만 늘린다 (비용 없음) — 정식 출시 전 재검토 (OQ-009).
