## 0. 한눈에

- DeepSearch는 일반 질문에 **시각자료만 얹는 것이 아닙니다.** 검색과 답변 방식이 다릅니다: 사연을 쟁점으로 나누고, 쟁점마다 법령을 따로 찾고, 쟁점마다 답하며, 사실에 따라 답이 갈리는 곳은 경우를 나눠 씁니다.
- **시각자료에는 추가 비용이 없습니다.** 구조화 결과와 검증된 답변 문단으로 코드가 그립니다.
- 추가 비용은 두 곳에서 납니다: 구조화 호출(Haiku, 약 $0.001)과 더 긴 답변(근거·문단이 늘어남). Pro Max 기준 일반 질문 약 $0.075 → DeepSearch 약 $0.12 (1.6배).
- 양식으로 적는다고 토큰이 줄지는 않습니다. 사연은 전체 입력의 1~2%뿐입니다. 양식의 가치는 빠진 사실을 채워 **다시 묻는 횟수를 줄이는 것**입니다.

## 1. 일반 질문과 무엇이 다른가

| 단계 | 일반 질문 | DeepSearch |
|---|---|---|
| 질문 읽기 | Haiku가 검색 문장·판례 검색어를 뽑음 (출력 300토큰) | **사건 구조화**: Haiku가 당사자·사실 순서·쟁점 2~4개·확인할 사실을 뽑음 (출력 2,000토큰까지) |
| 검색 (법제처, 무료) | 문장 하나로 한 번 — 조문 5·판례 5 | 사연 전체 검색 + **쟁점마다 그 법률에서 조문을 따로** — 조문 10·판례 5까지 |
| 답변 (고른 모델 1회) | 문단 3~4개 | **쟁점마다 1~3문단**, 문단에 쟁점 번호. 사연에 없는 사실에 따라 갈리면 경우를 나눠 설명, 쟁점 사이 연결을 밝힘 |
| 인용 검증 | 원문 구절 대조 + 법제처 재조회 | 같음 |
| 화면 | 답변·근거·절차 타임라인 | + **사건 구조도(마인드맵) · 사실관계 흐름 · 쟁점별 근거 · 확인할 사실** |
| 질문 1건 상한 | Light $0.0015 · Pro $0.03 · Pro Max $0.15 | 2배: $0.003 · $0.06 · $0.30 |
| 모델 호출 수 | 2회 (Haiku 해석 + 답변) | 2회 (Haiku 구조화 + 답변) — 늘지 않음 |

구조에는 사용자가 적은 사실만 담습니다. 질문에 없는 숫자, 단정 표현, 개인정보 패턴, 조문·사건번호가 든 항목은 코드가 버립니다. 법률 판단은 인용 검증을 거치는 답변 문단에만 있습니다.

## 2. 실호출 결과 — 같은 사연, 두 방식

사연(직접 입력, 120자):

> 2년 전세기간동안 이의없이 임대차가 계속 중임차인이 보증금 반환을 요구하였지만 임대인이 4개월동안 아무런 답변도 없어서 임차인의 임대차가 계속되는줄 알고 있는 중에 임대인이 갑자기 명도청구하는 경우 임차인의 대응방법

| | 1차 = 일반 답변 방식 (근거만 확대) | 2차 = DeepSearch |
|---|---|---|
| 입력 / 출력 토큰 | 12,070 / 1,981 | 14,646 / 3,082 |
| 추정 비용 (전부 Opus 단가로 친 상한) | $0.088 | $0.120 |
| 시간 | 30.6초 | 30.3초 |
| 답변 문단 | 4 (모두 검증 통과) | 6 (검증 통과 5, 구절 확인 필요 1) |
| 쓴 근거 | 주택임대차보호법 제6조·제6조의2·제4조 | 같은 세 조문 |
| 쟁점 구분 | 없음 | 3개: 묵시적 갱신 성립 여부 / 임대인의 갱신거절 통지 / 보증금 반환과 명도의 관계 |
| 사실에 따른 경우 나눔 | 일부 ("통지가 있었는지 확인") | 명시적: "기간이 끝나기 2개월 전까지 요구했다면 … 그렇지 않았다면 …" |
| 확인할 사실 | 없음 | 5개 (갱신거절 통지 여부, 서면 통지 여부, 소송인지 내용증명인지, 요구 시점과 만료 시점의 선후 등) |
| 시각자료 | 없음 | 사건 구조도 · 사실관계 흐름 4단계 · 쟁점별 근거 |

읽어 본 판단:
- **DeepSearch가 더한 것**: 이 사연의 핵심은 "보증금 반환 요구가 언제였는가"입니다. 만료 전이면 갱신이 안 될 수 있고, 갱신 뒤면 해지 통지로 볼 수 있어 3개월 뒤 효력이 문제 됩니다. DeepSearch는 이 갈림을 문단 2·3에서 경우로 나눠 설명했고, "확인할 사실"에도 같은 질문이 올라왔습니다. 일반 답변도 해지 통지 가능성은 짚었지만 경우를 나누지는 않았습니다.
- **같은 점**: 두 방식 모두 같은 세 조문을 썼습니다. 이 사연에 직접 닿는 판례(묵시적 갱신 뒤 임대인의 인도 청구)는 두 번 다 검색 결과에 없어 쓰지 못했습니다. 깊이를 더 올리려면 판례 검색이 먼저입니다.
- **아쉬운 점**: 2차의 한 문단은 인용 구절이 원문과 글자 그대로 맞지 않아 "확인 필요"로 표시됐습니다(예시에는 넣지 않음). 쟁점 1과 2는 내용이 겹칩니다.
- **1차가 실패한 이유**: 구조화 출력 한도(1,000토큰)를 넘겨 잘린 것으로 추정합니다(확인은 못 함). 한도를 2,000으로 늘린 뒤 2차는 성공했습니다. 실패하면 일반 답변으로 내려가도록 만들어 두어서 1차도 답은 나갔습니다. 이제 실패 이유가 결과 기록(프롬프트 버전)에 남습니다.

## 3. 직접 입력을 양식으로 옮기면

| 칸 | 옮긴 내용 | 원문에서 온 곳 |
|---|---|---|
| 무슨 일이 있었나요 (필수) | 2년 전세 계약 기간이 끝난 뒤에도 서로 이의 없이 계속 살고 있었어요. 그러던 중 제가 임대인에게 보증금을 돌려 달라고 요구했는데, 임대인은 4개월 동안 아무 답도 하지 않았어요. 답이 없어서 임대차가 계속되는 줄 알고 살고 있었는데, 임대인이 갑자기 집을 비워 달라고(명도) 청구했어요. | 사실 전체를 일어난 순서로 |
| 상대방은 누구인가요 (필수) | 임대인 (집주인) | "임대인" |
| 지금까지 한 일 | 보증금 반환을 요구했어요. | "보증금 반환을 요구하였지만" |
| 가지고 있는 자료 | (원문에 없어 비움) | — |
| 알고 싶은 것 (필수) | 임대인의 명도 청구에 임차인이 어떻게 대응할 수 있나요? | "임차인의 대응방법" |

옮길 때의 원칙: 원문에 없는 사실은 더하지 않습니다. 원문은 한 문장에 주어가 섞여 있어("계속 중임차인이") 누가 무엇을 했는지 헷갈리는데, 양식은 순서와 주어를 풀어 쓰게 만듭니다. 이 양식 내용은 DeepSearch 창의 "양식에 예시 채워 보기"로 넣어 볼 수 있습니다.

**양식이 정말 도움이 되는 곳**: 이 사연에서 답을 가르는 사실(요구한 시점, 통지 방법, 임대인이 통지했는지)은 원문에도 양식에도 없습니다. 양식의 "무슨 일이 있었나요" 안내(언제·순서·금액)와 보내기 전 점검이 이런 빈칸을 채우게 유도합니다. 채워서 보내면 "경우에 따라"가 아닌 그 경우의 답을 받을 수 있고, 다시 묻는 호출 1건(Pro Max 약 $0.08~0.12)을 아낍니다.

### 토큰은 같은가 (무료 토큰 세기로 측정)

| 입력 방식 | 글자 수 | 토큰 (Haiku·Sonnet·Opus 같음) |
|---|---|---|
| 직접 입력 (원문) | 120 | **130** |
| 양식 — 짧게 옮김 (머리말 3개 + 원문 수준 문장) | 138 | **152** |
| 양식 — 위 표처럼 풀어 씀 | 234 | **251** |

- 양식이 토큰을 줄여 주지는 않습니다. 머리말("[있었던 일]" 등)과 풀어 쓴 문장만큼 22~121토큰 늘어납니다.
- 다만 이 차이는 무시할 수준입니다. DeepSearch 1건 입력 14,646토큰 가운데 사연은 130~251토큰(**1~2%**)이고, 나머지는 근거 원문과 지시문입니다. Opus 기준 121토큰 차이는 $0.0005입니다.
- 양식이 비용을 지키는 지점은 **상한**입니다. 칸마다 길이가 정해져 있어 합쳐도 2,000자를 넘지 않습니다(직접 입력도 2,000자 한도는 같습니다).

|---|---|---|---|

추정의 근거:
- 구조화 호출: 입력 3,069토큰(토큰 세기 실측 — 지시문·사연 1,002 + 출력 형식 정의 2,067), 출력 약 900토큰으로 가정 → Haiku $0.0003 + $0.0005.
- DeepSearch 답변 입력은 2차 실측(14,646)에서 구조화 입력을 뺀 약 11,600토큰. Haiku·Sonnet은 생각 토큰이 없어 출력을 약 1,400토큰(6문단 + 인용 구절 + JSON)으로 가정했습니다.
- Light는 DeepSearch 상한($0.003)에 거의 닿습니다. 상한을 넘으면 근거를 뒤에서부터 빼므로, Light에서는 넓힌 근거가 일부 줄어들 수 있습니다.

### 토큰당 효율 (Pro Max 실측 기준)

| | 일반 질문 (22건 평균) | DeepSearch (2차 1건) |
|---|---|---|
| 검증 통과 문단 | 3.5개 | 5개 |
| 문단 1개당 출력 토큰 (생각 포함) | 약 510 | 약 620 |
| 문단 1개당 비용 | 약 $0.021 | 약 $0.024 |
| $1로 받는 검증 통과 문단 | 약 47개 | 약 42개 |
| 그 밖에 얻는 것 | — | 쟁점 구분 3 · 확인할 사실 5 · 사실 흐름 4 · 시각자료 (추가 비용 없음) |

- 문단당 비용은 거의 같습니다. DeepSearch는 "문단을 더 싸게" 만드는 기능이 아니라, 같은 단가로 **구조(쟁점·경우·확인할 사실)를 함께** 받는 기능입니다.
- 참고(일반 질문, 11-18 실측): Sonnet은 $1당 검증 통과 문단 약 140개, Haiku는 약 3,300개입니다. 다만 Haiku는 질문을 비껴가는 답이 있었고 Sonnet은 4문단 중 1문단이 구절 불일치였습니다. 문단 수만으로 품질을 비교할 수는 없습니다.

## 5. DeepSearch에는 어떤 모델이 맞는가

- **구조화는 Haiku** — 사연에서 사실과 쟁점을 뽑는 추출 작업이고, 결과를 코드가 다시 거릅니다. 비싼 모델을 쓸 이유가 없습니다(약 $0.0008).
- **답변은 사용자가 고른 단계 그대로** 두되, 복잡한 사연에는 **Pro Max를 권합니다.** 쟁점이 서로 물려 있고(앞 쟁점의 답에 따라 뒤 쟁점이 달라짐) 사실에 따라 경우를 나눠야 하는 일은 답하기 전에 생각하는 모델이 유리합니다. 이번 실측에서도 경우 나눔과 쟁점 연결이 나왔습니다.
- 비용이 걱정되면 **Pro(Sonnet)** 가 Pro Max의 약 1/3 가격입니다(추정 $0.038). 다만 Sonnet·Haiku로 DeepSearch를 실제로 불러 본 적은 없어 품질은 확인하지 못했습니다.
- 화면에서는 DeepSearch를 누를 때 단계를 강제로 바꾸지 않습니다. 고른 단계 그대로 분석합니다.

## 6. 시각자료는 어떻게 만드는가

재료는 두 가지뿐입니다: ① 구조화 호출이 뽑고 코드가 거른 사건 구조(`deep`) ② 인용 검증을 통과해 남은 답변 문단. 모델을 더 부르지 않고 `components/result/DeepMapView.tsx`가 그립니다.

| 그림 | 보여 주는 것 | 만드는 법 |
|---|---|---|
| 사건 구조도 (마인드맵) | 가운데 "이 사건", 오른쪽에 쟁점과 그 근거 이름, 왼쪽에 당사자와 확인할 사실(점선) | SVG. 글자 수로 줄을 나누고 칸 높이를 계산해 배치, 곡선으로 연결 |
| 사실관계 흐름 | 사연에 적힌 사실을 순서대로, 누가·언제 | 번호가 붙은 세로 흐름 |
| 쟁점별 근거 | 쟁점마다 답변 문단 번호와 쓴 조문·판례 | 남은 문단의 순번을 쟁점에 다시 이음 (검증에서 빠진 문단은 그림에서도 빠짐) |
| 확인할 사실 | 답이 달라질 수 있는데 사연에 없는 사실 | 체크 목록 |

지킨 규칙: 개수와 연결 같은 사실만 그립니다. 유불리·가능성·점수·게이지는 없습니다(절대 규칙 2). 머리에 "AI 생성 · 법률 자문 아님"을 붙입니다(절대 규칙 6).

이번 실호출 결과로 그린 화면은 예시로 저장해 두었습니다: **`/examples/deep-lease-01`** (DeepSearch 창의 "저장된 심층 분석 결과 보기"). 저장된 결과를 보여 줄 뿐이라 질문 횟수·비용이 들지 않습니다.

## 7. 함께 고친 것

- **절차 타임라인이 쓰지 않은 근거에 끌려가던 문제**: 검색에 섞여 들어온 "상가건물 임대차보호법" 때문에 주택 전세 사연이 일반 금전 절차로 분류됐습니다. 답변이 실제로 쓴 조문이 있으면 그 법령만 보도록 고쳤습니다(빌려준 돈 예시가 교통사고로 분류됐던 것과 같은 원인).
- **긴 법령 이름의 인용 검증 오탐**과 **기본 조문 검색 보강**은 `2026-11-19_예시_답변_22건_성능_분석.md` 6절에 적었습니다.

## 8. 측정 한계

- DeepSearch 실호출은 사연 1건, Pro Max 1번(성공한 것 기준)입니다. 경향일 뿐입니다.
- 1차 실패 원인은 추정입니다. 한도를 늘린 뒤 성공했다는 것 말고는 확인하지 못했습니다.
- 비용은 입력·출력 토큰 전부를 Opus 단가로 친 상한 추정입니다. 실제 청구는 Console 사용량에서 확인해야 합니다.
- Haiku·Sonnet의 DeepSearch 비용은 계산값이고, 품질은 불러 보지 않아 모릅니다.
- 로컬에서 띄운 production 빌드(같은 DB)로 실행했습니다.

## 9. Sonnet·Haiku DeepSearch 실측 (2026-11-19 추가)

4절의 추정 칸을 확인하려고 같은 사연(끝 문구만 다름 — 저장된 예시와 같은 문장이면 재생되므로)을 단계마다 1번씩 불렀습니다. 비용은 호출별 모델 단가로 나눠 계산한 값입니다(구조화는 Haiku).

| | Light (Haiku) | Pro (Sonnet) | Pro Max (Opus, 앞의 2차) |
|---|---|---|---|
| 입력 / 출력 토큰 (합계) | 13,730 / 2,173 | 14,444 / 1,897 | 14,646 / 3,082 |
| 비용 | **약 $0.0025** | **약 $0.034** | $0.120 이하 (호출별로 나누면 약 $0.09) |
| 4절 추정과 비교 | 추정 $0.0027 — 맞음 | 추정 $0.038 — 맞음 | — |
| 시간 | 14.7초 | 18.0초 | 29.5초 |
| 쟁점 | 2개 | 3개 (1개는 답한 문단 없음) | 3개 |
| 답변 문단 | 5 (모두 검증 통과, 1문단은 그 전에 걸러짐) | 4 (모두 검증 통과, 1문단은 그 전에 걸러짐) | 6 (검증 5, 구절 확인 필요 1) |

읽어 본 판단:
- **세 단계 모두 DeepSearch가 설계대로 동작했습니다** (구조화 성공, 쟁점별 답변, 인용 검증 통과).
- Haiku는 쟁점을 2개로 묶었고 임차권등기명령까지 안내했습니다. 가격은 Pro Max의 약 1/40입니다.

- 사연 1건씩이라 경향일 뿐입니다. Light의 DeepSearch 상한($0.003)에는 여유가 조금밖에 없었습니다(실측 $0.0025).
