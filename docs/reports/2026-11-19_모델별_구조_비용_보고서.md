
| 항목 | 이전 | 현재 | 왜 |
|---|---|---|---|
| 모델 정하는 사람 | 운영자 (환경변수 + 재배포) | **사용자** (질문마다) | 같은 서비스 안에서 속도·깊이를 고르게 |

| 답변 시간 초과 | 오류로 끝남 | **AI 문단 없이 근거만** (11-19 main에 반영) | 느린 Opus가 질문 실패로 이어지지 않게 |

## 2. API 비용 소모 구조 — 무엇이 바뀌었나

### 2.1 질문 1건에서 돈이 드는 곳

| 단계 | 모델 | 입력 | 출력 | 비용 |
|---|---|---|---|---|
| 법제처 검색 · 인용 검증 | 없음 | — | — | **0** (공식 API 무료) |
| 토큰 세기 (상한 확인) | — | — | — | **0** (무과금) |
| 절차 분류·질문 해석 (Haiku 1회) | Haiku | 약 1,500~2,000 | ≤300 | 약 $0.0003 |
| 답변 — Light | Haiku | 약 6,800 (조문 6·판례 3) | 약 550 | 약 $0.001 |
| 답변 — Pro | Sonnet | 약 6,800 (실측 6,765) | 약 800 (실측 784) | 약 $0.021 (실측 $0.0214) |
| 답변 — Pro Max | Opus | 약 6,800 | 약 800 + 생각 | 약 $0.05~0.09 |

- **Pro Max 비용의 대부분은 생각 토큰입니다.** 입력 몫(약 $0.027)은 고정입니다. 출력은 $20/1M이라 생각 1,000토큰마다 $0.02씩 늘어납니다. 생각 양은 effort로만 조절됩니다. effort `low`이면 위 범위의 아래쪽, `medium`이면 위쪽으로 추정합니다(6절).
- 절차 분류(질문 해석)는 main에는 "답변과 같은 1건 상한 안"에서 씁니다. 단계 선택 작업에서는 "주간 1단위를 따로 차감"합니다. 합칠 때 하나로 정합니다(6절).

### 2.2 상한 장치

| 장치 | 이전 | 현재 |
|---|---|---|
| 호출 전 차단 (DEC-019) | 입력 + 출력 한도 전부가 1건 상한 안일 때만 보냄 | 그대로, 상한만 단계마다 |
| 근거 줄이기 | 넘으면 근거를 하나씩 빼고 다시 잼 | 그대로 |
| 실패 호출 비용 | 계획한 최대 비용을 쓴 것으로 셈 | 그대로 |
| 주간 상한 | **건수** — 모델을 주 중간에 바꾸면 금액이 어긋남 | **단위** — 단계가 섞여도 금액 기준으로 맞음 |

**단위로 세면서 고쳐지는 문제**: 건수로 세면 비싼 모델을 쓰다가 싼 모델로 바꿀 때 그 주 금액을 넘을 수 있었습니다. 예를 들어 Opus 571건 뒤 Sonnet으로 바꾸면 그 주 최대 약 $143이었습니다. 단위로 세면 Pro Max 1건은 80단위, Pro 1건은 20단위를 쓰므로, 어떻게 섞여도 상한 기준 금액은 주 $80을 넘지 않습니다.

### 2.3 상한 기준 차감과 실제 지출

| 단계 | 차감 (상한 기준) | 실제 비용 (추정) | 실제 ÷ 차감 |
|---|---|---|---|
| Light | $0.0015 (1단위) | 약 $0.001 | 약 70% |
| Pro | $0.03 (20단위) | 약 $0.021 | 약 70% |
| Pro Max | $0.12 (80단위) | 약 $0.05~0.09 | 약 40~75% |

차감은 상한 기준이라 실제 지출은 항상 주간 금액보다 적습니다. Pro Max는 생각 양에 따라 비용이 크게 흔들려 상한을 넉넉히 잡았습니다. 그래서 주간 금액의 절반 가까이를 실제로는 쓰지 못할 수 있습니다. 실측 뒤 Pro Max 상한(80단위)을 줄이는 것을 검토합니다.

| 사용자 선택 비율 (Light : Pro : Pro Max) | 주 $80(53,333단위)로 가능한 건수 | 그 건수를 다 쓰면 실제 지출 (추정) |

## 5. 추천 구조

### 5.1 기본값과 단계 구성 — 지금 설계 그대로 권합니다
- **기본 Pro (Sonnet)**: 실측으로 확인된 가성비가 가장 좋은 단계입니다.
- **Light (Haiku)**: 빠르고 거의 공짜입니다. 다만 예외·단서를 빠뜨리는 것이 실측됐습니다. 그래서 화면에 "짧고 빠른 답"이라고만 설명하고, 기본값으로는 쓰지 않습니다.
- **Pro Max (Opus)**: 원하는 사람만 고릅니다. 오래 걸리는 것(15~40초 추정)을 화면에 미리 알립니다.

### 5.2 공모전 당일 (11-20)
- 주 $80, 비로그인 하루 5회는 그대로 둡니다. 시연 중 Pro Max를 많이 고르면 주간 단위가 빨리 줄어드는 것만 유의합니다. 모두 Pro Max로 고르면 666건입니다.
- **합친 뒤 Pro Max 실확인 1건**(허락됨, 추정 약 $0.05~0.09): `scripts/live-compare.mjs`. 확인할 것은 아래 세 가지입니다.
  - 걸린 시간(60초 한도 안인지)
  - 출력 토큰 = 생각 + 답변
  - 결과가 `grounded`인지
- 실확인에서 1건이 $0.10을 넘거나 40초를 넘으면 effort를 `low`로 둡니다.

### 5.3 운영 (공모전 뒤)
- 주간 금액을 다시 정합니다. 이전 값 $21이면 모두 Pro일 때 주 700건입니다.
- Pro Max 실측값으로 80단위를 다시 정합니다(실측 평균의 약 1.5배 권장).

### 5.4 품질을 더 올릴 때 — 혼합안 (설계만, 구현 안 함)
- Haiku가 검색어 뽑기·재검색 → Sonnet 답변. 1건 상한 $0.06, 추정 약 $0.05.
- 단계로 넣는다면 "Pro + 깊은 검색" 같은 형태입니다. 11-18 비교에서 Opus 전체와의 차이 대부분이 재검색에서 나왔습니다.

## 6. 운영 방안 고찰 · 합칠 때 정할 것

1. **합칠 때 정할 것 (원래 세션에 전달함)**
   - **Pro Max effort**: 단계 선택 작업은 effort `low`입니다. 사용자 요청은 `medium`입니다. `medium`이면 생각이 늘어 출력 4,000토큰·$0.12 안에서 잘릴 수 있습니다. 출력 5,000·$0.15(100단위)로 올리는 것을 함께 검토해야 합니다.
   - **결정 번호**: main은 DEC-032~035를 다른 결정(마이페이지, 질문 해석, 홈 카테고리, Google 로그인)에 이미 썼습니다. 단계 선택은 새 번호가 필요합니다.
   - **절차 분류 두 가지**: main의 질문 해석(Haiku, 답변 상한 안)과 단계 선택 작업의 AI 절차 분류(Haiku, 1단위 별도 차감·라벨 저장) 중 하나로 정해야 합니다.
2. **1건 상한은 코드가 지킵니다.** 상한을 넘을 호출은 보내지 않습니다. 답변 호출이 출력 한도에 닿거나, 거절되거나, 시간을 넘기면 AI 문단 없이 검증된 근거만 보여 줍니다. 다만 분석 전체에는 시간 예산이 없습니다. 그래서 검색·Opus 답변·인용 재조회가 모두 느리면 라우트 한도 120초에 닿아 오류가 날 수 있습니다(비용 상한은 그때도 지켜집니다). 근거만 낸 결과도 비로그인 횟수 1회를 씁니다.
3. **Pro Max만의 위험**
   - 생각 양이 질문마다 달라 비용·시간이 흔들립니다.
   - 안전 분류기가 넓습니다. 걸리면 근거만 나갑니다.
   - 생각이 출력 한도를 다 쓰면 답변 없이 비용만 나갈 수 있습니다(최대 약 $0.11).
4. **공모전이 끝나면 되돌립니다** (DEC-031 임시값): 비로그인 하루 5회 → 3회, 주간 $80 → $21(또는 새 값). 단위로 세므로 주 중간에 바꿔도 금액이 어긋나지 않습니다.
