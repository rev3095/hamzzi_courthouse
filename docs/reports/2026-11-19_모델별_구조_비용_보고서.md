## 0. 요약

**구조**: 사용자가 질문마다 답변 단계를 고릅니다(DEC-036). **기본은 Pro**이고, 고른 값은 그 기기에만 기억합니다. 세 단계 모두 "질문 해석(Haiku) → 무료 법제처 검색 → 답변 1회 → 무료 인용 검증"으로 같고, **답변 모델만 다릅니다.** 단계는 요금제가 아니며 과금과 연결하지 않습니다(절대 규칙 5).

| | Light | **Pro (기본)** | Pro Max |
|---|---|---|---|
| 답변 모델 · 생각 | Haiku 5.5 · 끔 | **Sonnet 5.5 · 끔** | Opus 5.5 · effort **medium** (끌 수 없음) |
| 출력 천장 · 시간 한도 | 1,200 · 25초 | 1,200 · 25초 | 5,000(생각 포함) · 60초 |
| 질문 1건 상한 (코드가 강제) | $0.0015 | $0.03 | $0.15 |
| **질문 1건 실제 비용** | 약 $0.0013 (추정, 11-18 실측 $0.0009 + 해석) | 약 $0.022 (실측 $0.0214 + 해석) | **중앙값 $0.075, $0.059~0.089 (실측 26건)** |
| 걸린 시간 | 6~7초 | 8~12초 | 18~26초 (중앙값 22초) |
| 출력 토큰 | 약 550 | 약 800 | 평균 약 1,800 (천장의 약 36%) |
| **기간 예산 $95로 이 단계만 쓰면** | 약 73,000건 | 약 4,300건 | 약 1,270건 (1,070~1,610) |

**한 줄 결론**
- **가성비는 Pro가 가장 좋습니다.** 그래서 기본값이 Pro인 것이 맞습니다. Light보다 약 17배 비싸지만, Haiku가 빠뜨린 예외·단서를 실측으로 챙겼습니다.
- **Pro Max는 1건에 Pro의 약 3.4배 비용, 2배 넘는 시간이 듭니다.** 그만큼 인용 정확성과 신중함이 올라갔습니다. 예시 22건에서 남은 77문단은 인용 구절이 모두 원문과 일치했고, 배포 1건은 인용 4개가 모두 맞았습니다. **"매번 최대 출력 금지"도 지켜졌습니다.** 출력은 평균 천장의 약 36%였고, 1건 상한 $0.15에 닿은 호출은 없었습니다.
- **세 단계 모두 같은 근거를 받습니다.** "검색이 핵심 근거를 못 찾는" 한계는 Pro Max를 골라도 남습니다. 이 부분은 DeepSearch(쟁점별 검색, DEC-041)와 카테고리 기본 조문(DEC-028 확장)이 다룹니다.
- **11-25까지는 기간 예산 $95를 실제 비용으로 차감합니다**(DEC-040). 그래서 상한 기준으로 셀 때보다 같은 돈으로 Pro는 약 1.4배, Pro Max는 약 2배 많이 답합니다.

### 1.2 이전 vs 현재

```
이전 (11-18 배포)
  질문 → 무료 법제처 검색 → [서버가 정한 모델 하나] 답변 1회 → 무료 인용 검증
         모델 = AI_ANSWER_MODEL (기본 Sonnet). 사용자는 고를 수 없음
         예산 = 주 $80 ÷ 1건 상한 = 건수 (실제 비용과 무관)

현재 (main ee001ed)
  질문 + 단계(light | pro | max, 없으면 pro) [+ DeepSearch 여부]
       → 질문 해석 Haiku 1회 (DeepSearch면 사건 구조화 Haiku 1회)
       → 무료 법제처 검색 (+ 카테고리 기본 조문, DeepSearch면 쟁점별 조문)
       → [단계의 모델] 답변 1회 → 무료 인용 검증
         Light  : Haiku,  생각 끔,     출력 ≤1,200, 25초, 상한 $0.0015 (DeepSearch $0.003)
         Pro    : Sonnet, 생각 끔,     출력 ≤1,200, 25초, 상한 $0.03   (DeepSearch $0.06)
         Pro Max: Opus,   생각 medium, 출력 ≤5,000, 60초, 상한 $0.15   (DeepSearch $0.30)
       예산 = 호출 전 상한만큼 잡아 두고 → 답변 뒤 실제 비용과의 차액을 돌려줌 (11-25까지)
```

| 항목 | 이전 | 현재 | 왜 |
|---|---|---|---|
| 모델 정하는 사람 | 운영자 (환경변수 + 재배포) | **사용자** (질문마다) | 같은 서비스 안에서 속도·깊이를 고르게 |
| Claude 호출 수 | 답변 1회 | 해석(또는 구조화) 1회 + 답변 1회 | 절차 라벨·검색어 정확도 (DEC-033) |
| 출력·시간 한도 | 모든 모델 같음 | 단계마다 | Opus는 생각 토큰도 출력 천장에 들어감 |
| 예산 차감 | 상한 기준 | **실제 비용** (11-25까지) | 크레딧을 다 쓰는 것이 목표 (사용자 결정) |
| 답변 시간 초과 | 오류로 끝남 | AI 문단 없이 근거만 | 느린 Opus가 질문 실패로 이어지지 않게 |

## 2. API 비용 소모 구조

### 2.1 질문 1건에서 돈이 드는 곳

| 단계 | 모델 | 입력 | 출력 | 비용 |
|---|---|---|---|---|
| 법제처 검색 · 인용 검증 · 토큰 세기 | 없음 | — | — | **0** |
| 질문 해석 | Haiku | 약 1,500~2,000 | ≤300 | 약 $0.0003 |
| (DeepSearch) 사건 구조화 | Haiku | — | ≤2,000 | 약 $0.001 |
| 답변 — Light | Haiku | 약 6,800 | 약 550 | 약 $0.001 |
| 답변 — Pro | Sonnet | 약 6,800 (실측 6,765) | 약 800 (실측 784) | 약 $0.021 (실측 $0.0214) |
| 답변 — Pro Max | Opus | 평균 약 9,700 (해석 몫 포함, 실측 22건) | 평균 약 1,800 (생각 포함, 실측) | 중앙값 $0.075 (실측) |
| 답변 — Pro Max DeepSearch | Opus | 14,646 (실측 1건) | 3,082 (실측 1건) | $0.120 (실측 1건) |

- **Pro Max 비용의 약 절반은 생각 토큰입니다.** 입력 몫(약 $0.035~0.039)은 근거 양으로 정해집니다. 출력 1,800토큰 중 답변 본문(문단 3~4개 × 180자)은 약 800토큰이고, 나머지가 생각입니다.
- Light·Pro DeepSearch 비용은 실호출하지 않은 계산값입니다([DeepSearch 비용 분석](2026-11-19_DeepSearch_특화_비용_분석.md)).

### 2.2 예산 장치 — 지금(11-25까지)과 그 뒤

| 장치 | 11-19 ~ 11-25 (DEC-040) | 11-26부터 (DEC-026·036, 코드 그대로 돌아감) |
|---|---|---|
| 1건 상한 | 단계 상한 (호출 전에 막음, DEC-019) | 같음 |
| 전체 상한 | 기간 하나 **$95** (`AI_PERIOD_BUDGET_USD`) | 주간 `AI_WEEKLY_BUDGET_USD` (토 09:00 시작) |
| 차감 | 호출 전 상한만큼 잡아 두고(`reserve_ai_budget`), 답변 뒤 **실제 비용과의 차액을 돌려줌**(`settle_ai_budget`) | 상한 기준 단위 차감 (돌려주지 않음) |
| 다 쓰면 | 기간 끝까지 강제 무료 모드 (법제처 검색만) | 그 주 무료 모드 |
| 오류로 끝난 분석 | 돌려주지 않음 (예산이 덜 남는 쪽으로만 틀림) | — |

**실제 비용으로 차감하면서 달라지는 점**: 상한 기준으로 셀 때는 Pro Max 1건이 $0.15를 썼지만, 지금은 실제로 쓴 약 $0.075만 씁니다. 같은 $95로 Pro Max는 633건 → 약 1,270건, Pro는 3,166건 → 약 4,300건이 됩니다. 이전 보고서에서 "공모전 뒤 권장"으로 적었던 정산이 이미 들어간 것입니다.

**남은 예산이 적을 때**: 호출 전에 그 단계 상한만큼 잡을 수 있어야 보냅니다. 그래서 남은 금액이 $0.15보다 적으면 Pro Max 질문은 무료 모드가 됩니다. 이때도 Pro($0.03)나 Light는 아직 될 수 있습니다.

### 3.2 기간 예산 $95 (11-19 ~ 11-25) — 단계 선택 비율에 따라

| 사용자 선택 비율 (Light : Pro : Pro Max) | 1건 평균 실제 비용 | $95로 가능한 건수 |
|---|---|---|
| 0 : 100 : 0 (모두 기본값) | $0.022 | 약 4,300건 |
| 10 : 80 : 10 | $0.025 | 약 3,800건 |
| 0 : 70 : 30 | $0.038 | 약 2,500건 |
| 0 : 0 : 100 (모두 Pro Max) | $0.075 | 약 1,270건 |
| 모두 Pro Max + DeepSearch | 약 $0.12 | 약 790건 |
| 100 : 0 : 0 (모두 Light) | $0.0013 | 약 73,000건 |

- 계산: 건수 = $95 ÷ 1건 평균 실제 비용. 질문 해석 비용 포함, 예시 질문 재생(비용 0)은 세지 않습니다.
- 공모전 시연과 크레딧 소진 목표(11-25까지)로 보면, Pro Max를 많이 골라도 예산이 금방 바닥나지 않습니다.
- 11-26부터는 주간 규칙으로 돌아갑니다. 상한 기준으로 차감하므로, 예를 들어 주 $80이면 모두 Pro일 때 2,666건, 모두 Pro Max일 때 533건입니다. 그 뒤 금액은 사용자가 다시 정합니다.

## 4. 성능 대비 API 소모량 (performance)

### 4.1 답변 품질 (점수 없이 항목 비교)

| 항목 | Light (Haiku) | Pro (Sonnet) | Pro Max (Opus) |

| 지어낸 인용 · 단정 표현 | 0 · 0 | 0 · 0 | 0 · 0 |
| 인용 구절 원문 일치 | 1건 비움 | 배포 1건에서 4개 중 3개 | **22건: 남은 77문단 모두 일치 · 배포 1건: 4개 모두** |
| 검증에서 빠진 문단 | — | — | 22건에서 86문단 중 9문단 (10.5%) |

| 핵심 근거가 검색에 없을 때 | 못 다룸 | 못 다룸 | 못 다룸 |

### 4.2 비용 대비 효과

| 비교 | 비용 · 시간 | 품질 차이 | 판단 |
|---|---|---|---|
| Light → Pro | 약 17배 (1.8원 → 31원) · 1.5배 | 예외·단서·질문 정렬이 **실측으로 크게** 좋아짐 | **값어치 있음 → 기본값** |
| Pro → Pro Max | 약 3.4배 (31원 → 105원) · 약 2배 | 인용 정확성·신중함이 올라감. 근거가 같으면 답의 깊이는 비슷 | **고르는 단계로 적당** |
| 일반 → DeepSearch (Pro Max) | 약 1.6배 ($0.075 → $0.120) | 쟁점별 검색·답변으로 근거 자체가 늘어남 | 검색 한계를 다루는 쪽. 실측 1건뿐 |

**정리**: 답변 1회 구조에서 품질 한계의 대부분은 **검색**에 있습니다. 모델을 올리면 같은 근거를 더 정확하고 신중하게 쓰지만, 없는 근거를 만들지는 못합니다. 그래서 다음으로 투자할 곳은 Pro Max 비중을 늘리는 것보다 검색 쪽(DeepSearch, 카테고리 기본 조문)입니다. 화면에는 "더 정확하다" 같은 약속 대신 답변 방식의 사실("생각을 더 하는 모델, 더 오래 걸림")만 적습니다(절대 규칙 2).

## 5. 추천 구조

### 5.1 단계 구성 — 지금 설계 그대로 권합니다
- **기본 Pro (Sonnet)**: 실측으로 가성비가 가장 좋습니다.
- **Light (Haiku)**: 빠르고 거의 공짜입니다. 다만 예외·단서를 빠뜨리는 것이 실측됐습니다. "짧고 빠른 답"으로만 설명합니다.
- **Pro Max (Opus, effort medium)**: 원하는 사람만 고릅니다. 오래 걸리는 것(약 20~30초)을 화면에 미리 알립니다.

### 5.2 토큰을 필요한 만큼만 쓰는 방법 (사용자 지시: "매번 최대 출력 금지")

| 방법 | 줄이는 것 | 상태 |
|---|---|---|
| 출력 5,000은 **천장**일 뿐, 목표로 쓰지 않음 | 불필요한 출력 | 실측 평균 1,800 (천장의 약 36%) |
| 답변 형식 고정: 문단 3~4개 × 180자 | 답변 몫 약 800토큰 | 세 단계 공통 |
| 근거 입력: 조문 6·판례 3건, 600·800자 (Pro Max라고 늘리지 않음) | 입력 토큰 | 세 단계 공통 (DeepSearch만 늘림) |
| 예산을 **실제 비용으로 차감** | 예산이 실제보다 빨리 닳는 것 | **적용됨** (DEC-040, 11-25까지) |
| 실측으로 effort·천장 다시 보기 | 추정과 실제의 차이 | 26건 실측: 모두 상한 안, effort medium 유지 |

### 5.3 11-25까지 (크레딧 우선 소진)
- 기간 예산 $95, 비로그인 하루 5회. 이 기간에는 한도를 낮추지 않습니다(사용자 결정).
- 지켜볼 것: 남은 기간 예산, 단계별 선택 비율, Pro Max 1건이 $0.10을 넘는 비율.

### 5.4 11-26부터
- 주간 규칙으로 자동으로 돌아갑니다(상한 기준 차감). 금액·하루 횟수는 사용자가 다시 정합니다.
- 권장: 실제 비용 차감(DEC-040 방식)을 주간 규칙에도 쓰는 것을 검토합니다. 상한 기준 차감은 Pro Max에서 예산의 절반가량을 쓰지 못하고 남깁니다.
- Pro Max 1건 상한 $0.15는 실측 최대 $0.089의 약 1.7배입니다. 생각이 긴 질문에 대비한 여유로 그대로 둡니다.

## 6. 운영 방안 고찰

1. **1건 상한은 코드가 지킵니다.** 상한을 넘을 호출은 보내지 않습니다. 답변 호출이 출력 천장에 닿거나, 거절되거나, 시간을 넘기면 AI 문단 없이 검증된 근거만 보여 줍니다. 다만 분석 전체에는 시간 예산이 없습니다. 검색·Opus 답변·인용 재조회가 모두 느리면 라우트 한도 120초에 닿아 오류가 날 수 있습니다(비용 상한은 지켜짐). 근거만 낸 결과도 비로그인 횟수 1회를 씁니다.
2. **Pro Max만의 위험**
   - 생각 양이 질문마다 다릅니다. 실측으로는 1건 $0.059~0.089, 18~26초 범위였습니다.
   - 안전 분류기가 넓어, 걸리면 근거만 나갑니다.
   - 생각이 출력 천장을 다 쓰면 답변 없이 비용만 나갈 수 있습니다(최대 약 $0.14).
   - 실측 기록에서 이 두 경우로 답이 빈 사례는 보고되지 않았습니다. 예시 22건 중 답이 빈 1건(보이스피싱)은 인용 재조회에서 4문단이 모두 빠진 것으로, 모델이 아니라 검증 단계 문제입니다(그 보고서 2절). 같은 질문을 실제 사용자가 하면 과금되고 답이 빌 수 있어 확인이 필요합니다.
3. **DeepSearch**: 구조화 단계가 실패하면 일반 답변으로 내려갑니다(실측 2건 중 1건). 이때도 비용은 일반 질문 수준입니다.
4. **지켜볼 숫자**
   - 기간 예산 카운터(`rate_limit_hits`, 키 `global`)
   - `analysis_results`의 모델·토큰·시간
   - 단계별 선택 비율
   - Console 사용량과 코드 추정 금액의 대조. 아직 하지 않았습니다.
