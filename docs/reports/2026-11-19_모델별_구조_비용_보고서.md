### 1.2 이전 vs 현재

```
이전 (11-18 배포)
  질문 → 무료 법제처 검색 → [서버가 정한 모델 하나] 답변 1회 → 무료 인용 검증
         모델 = AI_ANSWER_MODEL (기본 Sonnet). 사용자는 고를 수 없음

현재 (단계 선택)
  질문 + 사용자가 고른 단계(light | pro | max, 없으면 pro)
       → 무료 법제처 검색 → [단계의 모델] 답변 1회 → 무료 인용 검증
         Light  : Haiku,  생각 끔,          출력 ≤1,200, 25초, 상한 $0.0015
         Pro    : Sonnet, 생각 끔,          출력 ≤1,200, 25초, 상한 $0.03
         Pro Max: Opus,   생각 medium,      출력 ≤5,000, 60초, 상한 $0.15
```

| 항목 | 이전 | 현재 | 왜 |
|---|---|---|---|
| 모델 정하는 사람 | 운영자 (환경변수 + 재배포) | **사용자** (질문마다) | 같은 서비스 안에서 속도·깊이를 고르게 |
| 단계를 안 보낸 요청 | — | Pro | 이전 동작(Sonnet)과 같게 |
| 출력·시간 한도 | 모든 모델 같음 | 단계마다 | Opus는 생각 토큰도 출력 한도에 들어감 |
| 주간 예산 | 건수 = 금액 ÷ 1건 상한 | **단위** = 금액 ÷ $0.0015, 단계마다 다르게 차감 | 단계가 섞여도 금액이 맞게 |
| 답변 시간 초과 | 오류로 끝남 | **AI 문단 없이 근거만** (11-19 main에 반영) | 느린 Opus가 질문 실패로 이어지지 않게 |

## 2. API 비용 소모 구조 — 무엇이 바뀌었나

### 2.1 질문 1건에서 돈이 드는 곳

| 단계 | 모델 | 입력 | 출력 | 비용 |
|---|---|---|---|---|
| 법제처 검색 · 인용 검증 | 없음 | — | — | **0** (공식 API 무료) |
| 토큰 세기 (상한 확인) | — | — | — | **0** (무과금) |
| 절차 분류·질문 해석 (Haiku 1회) | Haiku | 약 1,500~2,000 | ≤300 | 약 $0.0003 |
| 답변 — Light | Haiku | 약 6,800 (조문 6·판례 3) | 약 550 | 약 $0.001 |
| 답변 — Pro | Sonnet | 약 6,800 (실측 6,765) | 약 800 (실측 784) | 약 $0.021 (실측 $0.0214) |
| 답변 — Pro Max | Opus | 약 8,800 (실측 합계 10,761에서 해석 몫을 뺀 추정) | 2,100 중 대부분 (생각 포함, 실측) | **약 $0.075~0.085** |

- **Pro Max 비용의 대부분은 생각 토큰입니다.** 입력 몫(약 $0.027)은 고정입니다. 출력은 $20/1M이라 생각 1,000토큰마다 $0.02씩 늘어납니다. 생각 양은 effort로만 조절됩니다. 사용자 결정(11-19)은 **effort `medium`**이라, 위 범위의 위쪽($0.07~0.09)에 가까울 것으로 추정합니다.
- 절차 분류(질문 해석)는 main에는 "답변과 같은 1건 상한 안"에서 씁니다. 단계 선택 작업에서는 "주간 1단위를 따로 차감"합니다. 합칠 때 하나로 정합니다(6절).

### 2.2 상한 장치

| 장치 | 이전 | 현재 |
|---|---|---|
| 호출 전 차단 (DEC-019) | 입력 + 출력 한도 전부가 1건 상한 안일 때만 보냄 | 그대로, 상한만 단계마다 |
| 근거 줄이기 | 넘으면 근거를 하나씩 빼고 다시 잼 | 그대로 |
| 실패 호출 비용 | 계획한 최대 비용을 쓴 것으로 셈 | 그대로 |
| 주간 상한 | **건수** — 모델을 주 중간에 바꾸면 금액이 어긋남 | **단위** — 단계가 섞여도 금액 기준으로 맞음 |

**단위로 세면서 고쳐지는 문제**: 건수로 세면 비싼 모델을 쓰다가 싼 모델로 바꿀 때 그 주 금액을 넘을 수 있었습니다. 예를 들어 Opus 571건 뒤 Sonnet으로 바꾸면 그 주 최대 약 $143이었습니다. 단위로 세면 Pro Max 1건은 80단위, Pro 1건은 20단위를 쓰므로, 어떻게 섞여도 상한 기준 금액은 주 $80을 넘지 않습니다.

### 2.3 상한 기준 차감과 실제 지출

| 단계 | 차감 (상한 기준) | 실제 비용 (추정) | 실제 ÷ 차감 |
|---|---|---|---|
| Light | $0.0015 (1단위) | 약 $0.001 | 약 70% |
| Pro | $0.03 (20단위) | 약 $0.021 | 약 70% |
| Pro Max | $0.15 (100단위) | 약 $0.075~0.085 (실측 1건) | 약 50~57% |

차감은 상한 기준이라 실제 지출은 항상 주간 금액보다 적습니다. Pro Max는 생각 양에 따라 비용이 크게 흔들려 상한을 넉넉히 잡았습니다. 그래서 주간 금액의 절반 가까이를 실제로는 쓰지 못할 수 있습니다. 실측 뒤 Pro Max 차감(100단위)을 줄이거나, 분석 뒤 실제 비용만큼만 차감하도록 정산하는 것을 검토합니다(5.2절).

### 3.2 주간 — 같은 $80에서 단계 섞임에 따라

이전에는 서버가 모델 하나를 정했으므로 주간 건수가 하나로 정해졌습니다(Sonnet 2,666건). 지금은 사용자 선택에 따라 달라집니다.

| 사용자 선택 비율 (Light : Pro : Pro Max) | 주 $80(53,333단위)로 가능한 건수 | 그 건수를 다 쓰면 실제 지출 (추정) |

| 0 : 100 : 0 (모두 기본값) | 2,666건 | 약 $56 |

| 0 : 70 : 30 | 1,212건 | 약 $47 |

### 4.2 비용 대비 효과

| 비교 | 비용 차이 | 품질 차이 | 판단 |
|---|---|---|---|

Pro Max 실측 1건도 같았습니다. 인용은 모두 맞았지만, 이 상황의 핵심 근거(임차권등기명령, 동시이행 일반론)는 이번에도 검색에 없었습니다. 다만 Sonnet과 Opus 실행 사이에 질문 해석이 추가돼 받은 근거가 달랐으므로, 모델만의 차이로 읽으면 안 됩니다. 화면에는 "더 정확하다" 같은 약속 대신, 답변 방식의 사실("생각을 더 하는 모델, 더 오래 걸림")만 적는 것이 맞습니다(절대 규칙 2).

## 5. 추천 구조

### 5.1 기본값과 단계 구성 — 지금 설계 그대로 권합니다
- **기본 Pro (Sonnet)**: 실측으로 확인된 가성비가 가장 좋은 단계입니다.
- **Light (Haiku)**: 빠르고 거의 공짜입니다. 다만 예외·단서를 빠뜨리는 것이 실측됐습니다. 그래서 화면에 "짧고 빠른 답"이라고만 설명하고, 기본값으로는 쓰지 않습니다.
- **Pro Max (Opus)**: 원하는 사람만 고릅니다. 오래 걸리는 것(실측 약 28초)을 화면에 미리 알립니다.

### 5.2 토큰을 필요한 만큼만 쓰는 방법 (사용자 지시: "매번 최대 출력 금지")
출력 5,000토큰은 답변이 잘리지 않게 두는 **천장**입니다. 과금은 실제로 쓴 토큰만 되고, 천장까지 쓰게 하는 장치는 없습니다. 실제 사용량을 작게 유지하는 방법은 아래와 같습니다.

| 방법 | 줄이는 것 | 상태 |
|---|---|---|
| 답변 형식 고정: 문단 3~4개, 문단마다 180자 (`LITE_ANSWER_SYSTEM`) | 답변 몫 약 800토큰 안팎 | 지금도 적용, Pro Max도 같은 프롬프트 |
| "길게·자세히" 같은 지시를 넣지 않음 | 천장을 목표처럼 쓰는 것 | 원칙 |
| 생각은 effort `medium`이 정하고, 프롬프트에 "근거와 질문을 대조하는 데 필요한 만큼만 생각" 한 줄 | 불필요하게 긴 생각 | 넣지 않음(73434fe). 실측 출력이 천장의 40%라 지금은 필요 없음 (생각을 금지하는 문장은 넣지 않음) |
| 근거 입력은 조문 6·판례 3건, 600·800자 그대로 (Pro Max라고 늘리지 않음) | 입력 토큰 | 지금도 적용 |
| 주간 예산을 분석 뒤 실제 비용만큼만 차감 (상한과의 차이를 돌려줌) | 예산이 실제보다 빨리 닳는 것 | 제안 — DB 함수 변경이 필요해 공모전 뒤 권장 |
| 실확인 1건으로 생각 양 측정 → effort·천장 다시 정하기 | 추정과 실제의 차이 | **완료** — 출력 2,100(천장의 약 40%) |

### 5.3 공모전 당일 (11-20)
- 주 $80, 비로그인 하루 5회는 그대로 둡니다. 시연 중 Pro Max를 많이 고르면 주간 단위가 빨리 줄어드는 것만 유의합니다. 모두 Pro Max로 고르면 533건입니다.
- **Pro Max 실확인 1건 — 완료** (11-19 배포 사이트): 아래 세 가지 모두 기준 안이었습니다.
  - 걸린 시간: 답변 25.5초, 전체 대기 28.1초 (60초 한도 안, 기준 40초 안)
  - 출력 토큰: 2,100 (생각 + 답변, 기준 2,500 안, 천장 5,000의 약 40%)
  - 비용: 약 $0.075~0.085 (기준 $0.10 안, 상한 $0.15의 약 50~57%), 결과 `grounded`
- 그래서 effort `medium`(사용자 결정 11-19)을 그대로 둡니다. 운영 중 출력이 2,500토큰, 1건이 $0.10, 대기가 40초를 자주 넘으면 `low`로 낮출지 다시 정합니다.

### 5.4 운영 (공모전 뒤)
- 주간 금액을 다시 정합니다. 이전 값 $21이면 모두 Pro일 때 주 700건입니다.
- Pro Max 차감 100단위는 실측 1건($0.075~0.085)의 약 1.8~2배입니다. 실측이 몇 건 더 쌓이면 실측 평균의 약 1.5배(약 80단위, $0.12)로 낮추는 것을 검토합니다.

### 5.5 품질을 더 올릴 때 — 혼합안 (설계만, 구현 안 함)
- Haiku가 검색어 뽑기·재검색 → Sonnet 답변. 1건 상한 $0.06, 추정 약 $0.05.
- 단계로 넣는다면 "Pro + 깊은 검색" 같은 형태입니다. 11-18 비교에서 Opus 전체와의 차이 대부분이 재검색에서 나왔습니다.

## 6. 운영 방안 고찰

1. **합칠 때 정한 것 (`73434fe`)**
   - **Pro Max 설정 — 결정 (사용자, 2026-11-19)**: effort `medium`, 출력 천장 5,000토큰, 1건 상한 $0.15(100단위). 계산: 입력 9,000($0.036) + 출력 5,000($0.10) = $0.136 ≤ $0.15. 작업본(effort `low`·4,000·$0.12·80단위)에서 이 값으로 바꿔 합쳤습니다. Light·Pro는 effort `low` 그대로입니다.
   - **결정 번호**: 단계 선택 DEC-036, AI 절차 분류 DEC-037, DeepSearch DEC-038, 내 질문 기록 DEC-039.
   - **절차 분류 — 둘 다 쓴다 (사용자 결정)**: 질문 해석(Haiku, 답변과 같은 1건 상한 안)을 먼저 하고, 해석 라벨·규칙이 못 정한 질문만 저장 라벨 → Haiku 분류(1단위 별도 차감)로 넘깁니다.
   - **하지 않은 것**: Pro Max 전용 프롬프트 줄, 주간 예산 실제 비용 정산(DB 함수 변경 필요, 공모전 뒤 권장).
2. **1건 상한은 코드가 지킵니다.** 상한을 넘을 호출은 보내지 않습니다. 답변 호출이 출력 한도에 닿거나, 거절되거나, 시간을 넘기면 AI 문단 없이 검증된 근거만 보여 줍니다. 다만 분석 전체에는 시간 예산이 없습니다. 그래서 검색·Opus 답변·인용 재조회가 모두 느리면 라우트 한도 120초에 닿아 오류가 날 수 있습니다(비용 상한은 그때도 지켜집니다). 근거만 낸 결과도 비로그인 횟수 1회를 씁니다.
3. **Pro Max만의 위험**
   - 생각 양이 질문마다 달라 비용·시간이 흔들립니다.
   - 안전 분류기가 넓습니다. 걸리면 근거만 나갑니다.
   - 생각이 출력 천장을 다 쓰면 답변 없이 비용만 나갈 수 있습니다(최대 약 $0.13). 5.2절의 방법으로 이런 경우를 줄이고, 실확인에서 생각 양을 봅니다.
4. **공모전이 끝나면 되돌립니다** (DEC-031 임시값): 비로그인 하루 5회 → 3회, 주간 $80 → $21(또는 새 값). 단위로 세므로 주 중간에 바꿔도 금액이 어긋나지 않습니다.
5. **지켜볼 숫자**
   - `analysis_results`의 모델·토큰·걸린 시간
   - 단계별 선택 비율(어느 단계를 얼마나 고르는지)
   - Anthropic Console 사용량. Console 금액과 코드 추정 금액을 하루 한 번 대조합니다.
6. **월 예산**: 주 $80이면 월 최대 약 $343입니다. 그래서 월 $100 프로모션 크레딧을 넘을 수 있습니다. 공모전 주만 $80으로 두는 것을 권합니다.
