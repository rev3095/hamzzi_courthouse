## 2. 방식 결정

### 2.1 Android — TWA (완료)
서버 기능(분석 스트림·Supabase·쿠키·로그인)이 Chrome 그대로 동작한다. Google 로그인도 Chrome 안이라 막히지 않는다. 앱은 기기의 Chrome과 쿠키를 공유한다.

### 2.2 iOS — 선택지 비교

| 선택지 | 내용 | 장점 | 위험·비용 | 판단 |
|---|---|---|---|---|
| A. PWA 안내 | Safari → 공유 → "홈 화면에 추가" | 지금 바로, 0원, 심사 없음 | 스토어 노출 없음 | **즉시 병행** |
| B. 단순 WebView 포장 | WKWebView로 사이트만 띄움 | 만들기 쉬움 | 지침 4.2로 **반려 가능성 높음**. Google 로그인은 WebView에서 막힘(403 `disallowed_useragent`) | 쓰지 않음 |
| C. Capacitor 셸 + 네이티브 기능 | 웹 화면은 배포 사이트, 바깥은 네이티브(시작 화면·오프라인 화면·공유 시트·햅틱·하단 탭·보관함 바로가기 등) | 웹 팀이 유지 가능, 4.2 대응 근거를 만들 수 있음 | macOS 빌드 필요, 4.2 심사는 여전히 판단 대상 | **권장** |
| D. 전부 네이티브(SwiftUI) | 화면을 Swift로 다시 만듦 | 심사 위험 가장 낮음 | 개발량 큼, 웹과 이중 관리 | 지금은 과함 |

**권장**: A를 바로 안내하고, Android 출시(P20) 뒤 C로 진행한다.
- iOS 첫 버전은 **로그인 없이**(비로그인 기능만) 내는 것을 권한다. 로그인을 넣으면 4.8(대안 로그인 — Sign in with Apple 등)과 5.1.1(v)(앱 안 계정 삭제)을 함께 갖춰야 하고, Google 로그인은 WebView가 아니라 시스템 인증 창(ASWebAuthenticationSession)으로 띄워야 한다.

## 3. Google Play 등록 절차 (P14~P21, 예시 포함)

상세는 `docs/08_Google_Play_배포.md`. 여기서는 순서와 예시만.

### P14. 개발자 계정 등록 — 사용자
1. https://play.google.com/console → Google 계정 로그인(앱 전용 계정 권장, 예: `hamzzi.court.dev@gmail.com`).
2. 계정 유형 **개인** → 등록비 25달러 결제.
3. 본인 확인: 법적 이름과 같은 신분증·카드. 예) 이름 "홍길동" = 주민등록증 "홍길동" = 카드 명의 "홍길동".
4. Android 폰에 **Play Console 앱** 설치 → 같은 계정 로그인(기기 확인).
5. 개발자 공개 정보: 이름 `햄찌법원`, 문의 이메일 예) `hamzzi.court.help@gmail.com`.

### P15. 업로드 키 · 첫 AAB · 내부 테스트 — 사용자
```bash
keytool -genkeypair -v -keystore twa/upload-keystore.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```
```bash
pnpm android:build
```
```bash
jarsigner -keystore twa/upload-keystore.jks twa/dist/hamzzi-court-1.0.0-vc1-unsigned.aab upload
```
- keytool 질문 예시 답: 이름 `Hamzzi Court` / 조직 `Hamzzi` / 도시 `Seoul` / 국가 `KR` → `yes`. 비밀번호는 직접 정해 비밀번호 관리자에 저장(채팅·저장소에 쓰지 않음).
- `upload-keystore.jks`는 저장소 밖 두 곳에 백업.
- Play Console: **앱 만들기**(햄찌법원·한국어·앱·무료) → **테스트 및 출시 → 내부 테스트 → 테스터**(이메일 목록 `내부`) → **새 버전 만들기**에 서명한 AAB → 출시 노트 `<ko-KR>첫 내부 테스트 버전</ko-KR>` → 테스터 링크로 설치.

### P16. 사이트 연결(assetlinks) — 사용자가 지문 전달, Claude가 반영
1. **테스트 및 출시 → 설정 → 앱 무결성 → 앱 서명** → "앱 서명 키 인증서" SHA-256 복사.
   예) `14:6D:E9:83:…:3F:CF:44:E5` (공개 값이라 채팅으로 보내도 됨)
2. Claude가 `public/.well-known/assetlinks.json`에 넣고 배포.
3. 폰에서 앱을 열어 **주소 표시줄이 없으면** 성공.

### P17. 정책 준비(웹 수정) — 정보는 사용자, 반영은 Claude

- 개인정보처리방침 3절의 국외 이전 고지(현재 "법무 검토 중")와 함께 정한다. 무료 모드·예시 질문은 동의가 필요 없다.

4. 사업자로 내려면 조직 가입(D-U-N-S 번호, 법인, 도메인 이메일·웹사이트 필요).

### P28. TestFlight — 사용자
- 내부 테스터(App Store Connect 사용자) 최대 100명 → 외부 테스터 최대 10,000명(첫 빌드는 베타 심사). 빌드는 최대 90일 테스트 가능.
- 예시 진행: 내부 3명 1주 → 외부 20명 1~2주(의견: 글자 크기·로딩·공유).

### P29. 심사 제출 · 반려 대응 — 사용자 제출, Claude 수정
- 반려 사유가 4.2(최소 기능)면: 네이티브 기능을 늘리고 심사 노트에 화면별로 적어 재제출하거나, Resolution Center에서 설명한다.
- 5.1.2(i)면: P23 동의 화면이 실제로 뜨는 경로를 스크린샷으로 첨부.

### P30. 출시 · 업데이트
- 웹 기능은 배포만으로 반영(셸이 사이트를 띄우는 구조). 셸 변경은 버전·빌드 번호를 올려 TestFlight → 심사.
- 연회비 갱신 일정을 달력에 넣는다.
