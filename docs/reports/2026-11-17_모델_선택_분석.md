**"생각 끄기"가 중요한 이유**: 생각 토큰은 출력 요금으로 청구됩니다. 지금 코드는 모든 호출에서 생각을 꺼서(`thinking: disabled`) 출력 길이를 고정하고, 그 덕분에 "질문 1건 상한"을 정확히 지킵니다. Opus 5.5·Fable은 생각을 끌 수 없어서(보내면 400 오류) **모델 이름만 바꾸면 지금 코드가 바로 실패합니다.** 바꾸려면 출력 한도를 생각 몫까지 넉넉히 잡아야 하고, 그만큼 상한도 올라갑니다.

### 토큰 수는 모델마다 같나 (count_tokens 실측)

라이트 답변과 같은 모양의 프롬프트(지시문 + 질문 + 근거 7개, 6,078자)를 모델마다 셌습니다.

| 모델 | 입력 토큰 |
|---|---|
| Fable 5.2 · 5.1 · Opus 5.5 · Sonnet 5.5 · Haiku 5.5 | 6,950 |
| Opus 5 · 4.8 · Sonnet 5 · Fable 5 | 6,948 |
| Opus 4.7 | 6,953 |
| Opus 4.6 · Sonnet 4.6 · 구형 4.5 3종 | 6,843~6,844 |

→ **한국어 프롬프트에서는 모델을 바꿔도 입력 토큰이 거의 같습니다(차이 2% 이내).** 그래서 비용 차이는 순전히 단가 차이입니다.

## 3. 품질과 과정 차이

### 3.1 라이트 vs 전체 파이프라인 (코드 기준 + 실측)

| 항목 | 라이트 (`lib/ai/lite.ts`) | 전체 (`lib/ai/orchestrator.ts`) |
|---|---|---|
| Claude 호출 수 | **1회** (답변) | 2~5회 (의도 1 + 재검색 0~3 + 답변 1) |
| 검색어 | 규칙으로 만듦 (LLM 없음, 무료 모드와 같음) | 모델이 사연에서 법률·조문 키워드·판례 검색어를 뽑음 |
| 재검색 | 없음 | 최대 3라운드, 라운드당 새 판례 3건. 실측 1~3라운드 (평균 1.5) |
| 모델에 넘기는 근거 | 조문 4 + 판례 3건까지, 원문 조문 600자·판례 800자 | 조문 5 + 판례 8건 + 재검색 추가분, 원문 900자·1,600자 |
| 답변 문단 | 3~4개, 문단당 180자 이내 | 3~6개 (실측 평균 5.0) |
| 실제로 쓴 근거 (실측) | 측정 없음 | 조문 1~6개, 판례 0~3건 |
| 시간 | 측정 없음 (호출 1회라 짧을 것으로 추정) | 실측 평균 약 38초, p95 46.6초 |
| 예산 초과 시 | 근거를 하나씩 빼고 다시 잼 → 그래도 넘으면 AI 문단 없이 근거만 | 재검색을 멈추고 답변 몫을 남김 → 그래도 넘으면 근거만 |

### 3.2 모델별 답변 품질

**먼저 알아 둘 점**: 지어낸 판례·조문·사건번호는 **어느 모델이든 화면에 나가지 않습니다.** 답변 문단마다 근거 키·원문 구절을 대조하고 법제처에 다시 조회하는 검증기(F-005)가 모델 밖에서 거르기 때문입니다. 모델이 바뀌면 달라지는 것은 ① 검증을 통과해 **살아남는 문단 수**, ② 문단의 **내용 질**(단서·예외, 다음 할 일, 질문에 바로 답하기, 한국어 문장)입니다.

| 모델 · 과정 | 허위 인용 | 근거와 맞음 | 단정 안 함 | 다음 할 일 안내 | 한국어 문장 | 근거 |
|---|---|---|---|---|---|---|
| **Opus 5.5 · 전체** | 0건 (4회 모두) | 10/12 | 10/12 | 9/12 | 자연스러움 (예시 10건) | **실측** — P9 마지막 회차, Sonnet 채점 |
| Haiku 5.5 · 라이트 (지금) | 0건 (구조상) | 미측정 | 미측정 | 미측정 | 미측정 | 측정 없음. 문단이 짧고(3~4개) 판례 활용이 적을 것으로 **추정** |
| Sonnet 5.5 · 라이트 | 0건 (구조상) | 미측정 | 미측정 | 미측정 | 미측정 | **추정**: 단서·예외 반영과 문장이 Haiku보다 좋고 Opus에 가까울 것 |
| Fable 5.2 · 라이트 | 0건 (구조상) | 미측정 | 미측정 | 미측정 | 미측정 | **추정**: 근거 7개 요약에는 능력이 남음. 생각이 항상 켜져 비용·시간 예측이 어려움 |

지난 평가에서 확인된 것 (`evals/README.md`):
- 재검색을 더 세게(effort medium) 해도 판례 후보만 늘고 **근거 충실도는 나아지지 않았습니다** → 충실도는 "검색"이 아니라 **"답변 쓰기"** 문제였습니다.
- 남은 실패 유형: 다음 할 일(기관·절차) 안내 부족 3건, 단정 유도 질문에 "보장되지 않는다"를 직접 말하지 않음 1건, 조문 사유를 섞어 설명 1건.
- 그래서 **같은 돈이면 재검색보다 답변 모델을 올리는 쪽이 품질에 더 효과적**이라고 판단합니다(추정 — 모델별 실측 없음).

## 4. 추천

### 4.1 사용자 조건
1. Haiku보다 품질을 많이 높이고 싶다 — 무료 크레딧(약 $100)을 조금 써도 된다.
2. **한 번에 돈이 많이 나가면 절대 안 된다.**

### 4.2 추천: 라이트 + Sonnet 5.5 답변

| 설정 | 값 | 하루 최대 / 월 최대 |
|---|---|---|
| 과정 | 라이트 (`AI_MODE=pro`, 호출 1회) | |
| 답변 모델 | `claude-sonnet-5-5`, 생각 끔(`between_tools`), effort `low` | |
| 질문 1건 상한 | **$0.03** (약 42원) | |
| 하루 전체 상한 `AI_DAILY_LIMIT` | **30건** (분석·문서 초안 합계) | **$0.90 / 약 $27** |
| Console 월 지출 한도 | **$30** (마지막 방어선) | |
| 문서 초안 도우미 | Haiku 그대로 ($0.0015) | |

**이유**
- **돈이 한 번에 크게 나갈 수 없습니다**: 질문 1건 최대 $0.03 × 하루 30건 = 하루 최대 $0.90. 상한을 넘을 호출은 코드(`withCostCap`)가 보내기 전에 막고, 하루 상한을 넘으면 그날은 무료 모드로 돌아갑니다. Console 월 한도 $30이 그 위를 한 번 더 막습니다.
- **호출이 1번이라 예측이 쉽습니다**: 생각을 끌 수 있어 출력이 1,200토큰을 넘지 않습니다. 전체 파이프라인처럼 재검색 라운드 수에 따라 비용이 흔들리지 않습니다.
- **품질 문제가 있던 단계(답변 쓰기)를 바로 올립니다.**
- **$100로 오래 갑니다**: 하루 30건을 매일 꽉 채워도 약 110일, 보통 사용량이면 그보다 깁니다.

| 선택지 | 1건 상한 | 하루 상한 추천 | 하루 최대 | 언제 |
|---|---|---|---|---|
| Haiku 5.5 그대로 | $0.0015 | 100건 | $0.15 | 비용을 거의 안 쓰고 싶을 때 |
| **라이트 Sonnet 5.5 (추천)** | **$0.03** | **30건** | **$0.90** | 품질을 크게 올리되 지출을 작게 |
| 혼합 (Haiku 검색 + Sonnet 답변) | $0.06 | 15건 | $0.90 | 라이트로 해 보고 "근거 폭이 좁다"고 느낄 때 |
| 라이트 Opus 5.5 | $0.09 | 10건 | $0.90 | 예시 질문과 같은 모델로 맞추고 싶을 때. 생각 토큰 때문에 비용이 들쭉날쭉 |
| 라이트 Fable 5.2 | $0.20 | 5건 | $1.00 | 비추천 — 이 작업에는 능력이 남고, 1건이 비싸며 느림 |
| 전체 Opus 5.5 | $0.25 | 4건 | $1.00 | 비추천 — 예전 약 $10 청구 때와 같은 구성 |

하루 최대를 약 $1로 맞추면, 어떤 모델을 골라도 "하루에 몇 달러씩 나가는" 일은 생기지 않습니다.

### 4.4 확인 방법 (돈이 드는 부분)
- 구현 검증은 **무료 검사만** 합니다 (가짜 모델 단위 테스트·린트·타입·빌드, 토큰 세기).
- 실제 답변 품질은 실호출로만 알 수 있습니다. 원하시면 배포 후 **질문 1건만** 확인합니다 — 예상 최대 $0.03(약 42원). 허락하실 때만 합니다(절대 규칙 8).

## 6. 모델 선택기 설계안 (구현은 모델을 고르신 뒤에)

### 6.1 지금 구조의 한계
- 모델이 `lib/ai/policy.ts` `MODELS`에 고정(전부 Haiku), 단가표 `lib/ai/cost.ts` `PRICES`에 Haiku만 있음 → 다른 모델은 `priceOf`가 막음(안전하지만 고를 수 없음).
- 모든 호출이 `thinking: { type: "disabled" }` → Sonnet 5.5·Opus 5.5·Fable에서는 400 오류.
- 문서 초안 도우미(`doc-draft.ts`)도 `MODELS.answer`를 써서, 답변 모델을 바꾸면 초안 비용도 같이 바뀜.
- 하루 상한은 "건수"라서, 비싼 모델로 바꾸면 하루 최대 금액이 조용히 늘어남.

### 6.2 설계
**환경변수** (Vercel에서 고름, 코드 기본값은 지금과 같음)

| 변수 | 값 | 기본 |
|---|---|---|
| `AI_MODE` | `free` / `pro`(라이트) / `pro-full` | free (그대로) |
| `AI_ANSWER_MODEL` | 허용 목록 중 하나: `claude-haiku-5-5` · `claude-sonnet-5-5` · `claude-opus-5-5` · `claude-fable-5-2` | `claude-haiku-5-5` |
| `AI_SEARCH_MODEL` | pro-full의 의도·재검색 모델 (같은 허용 목록) | `claude-haiku-5-5` |
| `AI_DAILY_BUDGET_USD` | 하루 최대 금액 | `1` |
| `AI_DAILY_LIMIT` | 하루 최대 건수 (있으면 금액 기준과 둘 중 작은 값) | 금액 ÷ 1건 상한 |

- 허용 목록 밖의 값·오타 → **Haiku로 돌아가고** 로그에 "알 수 없는 모델 설정"만 남김(값은 안 남김). 싼 쪽으로 실패하게.
- 하루 건수 = `min(AI_DAILY_LIMIT, floor(AI_DAILY_BUDGET_USD ÷ 1건 상한))` → 모델을 바꿔도 **하루 최대 금액은 늘지 않음.**

**모델 프로필 표** (`lib/ai/cost.ts`에 단가표와 함께, 순수 함수 → 무료 단위 테스트 대상)

| 모델 | 생각 설정 | effort | 라이트 출력 한도 (max / min) | 라이트 1건 상한 | 전체 1건 상한 |
|---|---|---|---|---|---|
| Haiku 5.5 | `disabled` | low | 1,200 / 700 | $0.0015 | $0.015 |
| Sonnet 5.5 | `between_tools` | low | 1,200 / 700 | $0.03 | $0.12 (혼합 $0.06) |
| Opus 5.5 | 보내지 않음 (항상 켜짐) | low | 3,000 / 1,500 (생각 몫 포함) | $0.09 | $0.25 |
| Fable 5.2 | 보내지 않음 (항상 켜짐) | low | 4,000 / 2,000 | $0.20 | — (허용 안 함) |

- 단가표 `PRICES`에 네 모델의 입력·출력·캐시 읽기·쓰기를 추가. 표에 없는 모델은 지금처럼 `priceOf`가 막음.
- **절대 상한 상수 `HARD_CAP_USD = 0.25`**: 어떤 설정으로도 1건 상한이 이 값을 넘지 않음.
- `withCostCap`·무과금 `countTokens` 사전 측정·`planCall`은 그대로. `max_tokens`가 생각 토큰까지 포함하므로 상한 계산은 생각 모델에서도 지켜짐.
- 생각 모델은 `max_tokens`에 닿으면 실패(과금은 됨) → 출력 한도를 넉넉히 잡는 이유. 실패하면 지금처럼 재시도 없이 근거만 보여 줌.

**함께 고칠 곳**
- `lib/ai/client.ts` `usageCost`: 응답의 실제 모델(`res.model`) 단가로 계산 (서버 fallback으로 다른 모델이 답했을 때 대비). 라이트에는 서버 fallback을 붙이지 않음 — 거절되면 근거만.
- `lib/ai/doc-draft.ts`: `MODELS.docDraft = "claude-haiku-5-5"`로 분리 (초안은 Haiku 고정).
- `lib/ai/key-check.ts`: 고른 답변 모델로 `models.retrieve` → 배포 후 `/api/v1/health`에서 그 모델에 접근 가능한지 무과금 확인.
- `analysis_results.model`에 이미 모델이 기록됨 → 나중에 모델별 비교 가능.
- 문서: PRD 결정 로그에 DEC-024(답변 모델 선택), CLAUDE.md 환경변수 절, `lib/ai/README.md`.

**검증 (모두 무료)**
- `cost.test.ts`: 모델마다 최악의 경우(입력 상한 + 출력 한도)가 1건 상한 안인지, `HARD_CAP_USD`를 못 넘는지.
- `policy.test.ts`: 모델별 생각 설정(Haiku `disabled`, Sonnet `between_tools`, Opus·Fable 없음), 환경변수 오타 → Haiku.
- 하루 건수 계산(금액 ÷ 상한), 문서 초안이 Haiku에 고정되는지.
- `pnpm lint` · `pnpm typecheck` · `pnpm test` · `pnpm build` · `pnpm docs:check`.

### 6.3 배포할 때 넣을 값 (추천안 기준, 사용자가 Vercel에서 직접)
