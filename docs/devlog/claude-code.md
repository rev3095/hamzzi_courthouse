# devlog — Claude Code 섹션 (답변 전문, 최신순)

VS Code의 Claude Code 세션이 사용자 요청마다 한 답변을 **요약하지 않고 그대로** 모았다. 위가 최신이다.

- 답변 16건 (요청 30건 가운데 긴 답변이 있는 것). 사용자 요청은 앞 900자만 실었다.
- 도구 호출·중간 진행 한 줄·시스템 알림은 뺐다. 한 요청에 계획이나 중간 보고가 따로 있었으면 "그 전에 한 답변"으로 접어 두었다.
- 저장소가 공개라 사용자 폴더 이름·키 모양 문자열·이메일은 가렸다. 답변 속 금액·수치는 그 시점의 값이다.
- 다시 만들기: `python -X utf8 scripts/build_devlog_claude_code.py <대화 기록.jsonl>` (대화 기록 파일은 저장소에 없다).
- 요약판·세션 계층·결정 색인은 [`../devlog.md`](../devlog.md)에 있다.

## 씨앗

- 글 1개에 10개, 댓글 1개에 5개, 씨앗 1개가 할인 1원 가치입니다. 글 100개와 댓글 200개가 각각 1,000원입니다.
- 로그인 사용자에게만 쌓입니다.
- 남용 방지로 하루에 씨앗을 받는 글은 5개, 댓글은 10개까지입니다. 너무 짧은 글은 제외하고, 지우면 회수합니다.

**Claude Code 답변**

lexdiff README의 기능을 1~3차 전부 독자 구현했고 무료 검사는 모두 통과했지만, 아직 커밋하지 않았고 지금 원격 main은 빌드가 깨진 상태입니다.

## 먼저 결정이 필요한 것

- **원격 main이 깨져 있습니다.** 작업 도중 다른 세션이 같은 폴더에서 `e08a9e2`(판례 검색 화면 가독성 개편)를 커밋·푸시했는데, 그 커밋에 제가 작업 중이던 [SearchView.tsx](components/search/SearchView.tsx)가 들어갔습니다. 이 파일은 아직 커밋되지 않은 제 파일들을 불러오므로, 제 변경을 커밋·푸시해야 그 커밋의 Vercel 빌드가 통과합니다. **푸시해도 될까요?**
- **다른 세션의 검색 화면 개편본을 제 저장이 덮어썼습니다.** 원본은 git에 남아 있지 않아, 그쪽 커밋 설명과 테스트를 기준으로 다시 만들어 탭 화면에 합쳤습니다(자주 찾는 검색어 8개, 결과 건수, 법원 칩, 19px 제목, 로딩 자리표시). 그쪽 테스트는 통과하지만 검색어 8개의 문구와 세부 모양은 원래와 다를 수 있습니다.

## 구현한 것

lexdiff 코드는 가져오지 않았고, 새 패키지도 설치하지 않았습니다. 이미 쓰고 있던 korean-law-mcp(MIT)의 법제처 조회 함수만 사용했습니다.

| README 기능 | 햄찌법원 |
|---|---|
| 판례·해석례 통합 | `/search` 탭 7개: 판례, 법령해석례, 헌재 결정례, 조세심판 재결례, 관세청 해석, 자치법규, 행정규칙 |
| 약칭·즉시 조회 | "민법 750조", "주택임대차법 제3조"(공식 약칭), 사건번호를 적으면 해당 조문·판례로 바로 이동 |
| 타임머신 | 조문 화면에서 날짜를 고르면 그날 시행 중이던 조문을 가져와 현행과 줄 단위로 비교 |
| 라이브 판례 패널 | 조문 화면에 "이 조문이 나오는 판례" 목록(스크롤을 따라 갱신되지는 않음) |
| 신구조문 비교·3단 비교·별표·영향 추적·위임 점검 | `/laws/법령명`의 탭 5개(개정 연혁에서 시점을 고르면 그 개정의 대조표) |
| 자치법규·조례 벤치마킹 | 조례 검색, 조문 보기, 두 지자체 나란히 보기 |
| 조회 이력 | 검색 화면의 "최근 본 자료"와 `Ctrl/Cmd+K` 빠른 열기(이 기기에만 저장) |

lexdiff와 다르게 둔 것:
- **AI 기능은 넣지 않았습니다.** 요약, 비교표, 심각도 분류, 기준일 답변은 유료 호출과 유불리 판단 금지 규칙 때문에 제외했습니다.
- **영향 추적과 위임 점검은 사실만 보여 줍니다.** 법제처에 등록된 관계와 개수만 표시하고 "입법 공백" 같은 판정은 하지 않습니다.
- **별표는 목록과 원문 파일 링크까지입니다.** 한글 파일을 표로 그려 주는 뷰어는 만들지 않았습니다.
- **조회 이력은 홈 화면에 넣지 않았습니다.** 홈은 Figma 기준 화면이라 검색 화면과 빠른 열기에만 두었습니다.

## 검사 결과

- 단위 테스트 500개, 타입 검사, 변경 파일 린트, `pnpm build`(재실행에서 통과), `docs:check`, 검색 화면 E2E 2개가 통과했습니다.
- 법제처 실호출 스모크 6개도 통과했습니다. 무료이고 Claude 호출은 없지만, 구조 확인용 조회와 함께 미리 여쭙지 않고 실행했습니다.
- `legal-reviewer`는 아직 돌리지 않았습니다. PR 전에 실행하겠습니다.

## 확인이 필요한 점

- **관세청 해석 탭**: 법제처에서 결과가 0건이고 상세는 500 오류였습니다. 인증키에 해당 자료 사용 승인이 없는 것으로 보입니다. 승인 전까지 탭을 숨길지 정해 주세요.
- **원문 링크**: 조세심판·관세청 자료는 공개 원문 주소를 확인하지 못해 번호만 보여 줍니다. 해석례·헌재·자치법규·행정규칙의 링크 주소는 제가 아는 형식으로 넣었고 실제로 열리는지는 확인하지 않았습니다.
- **Next.js 보안 권고**: 빌드 중 현재 버전(16.4.2)에 알려진 보안 취약점이 있다는 업그레이드 권고가 나왔습니다. 원하시면 별도 worktree에서 업그레이드를 진행하겠습니다.
- **DEC-026**: 이번 범위를 PRD에 "제안"으로 적어 두었으니 확정 여부를 봐 주세요. API 명세와 개인정보처리방침(최근 본 자료 저장 안내)도 함께 고쳤습니다.

## 먼저 알려드릴 것: lexdiff 코드는 운영 서비스에 쓸 수 없는 라이선스입니다

lexdiff 저장소는 **BSL 1.1** 라이선스이고, README에도 "프로덕션 환경에서의 사용 금지"라고 적혀 있습니다(2030-04-14에 Apache 2.0으로 전환).

- **무료인 것은 데이터입니다.** 법제처 공공데이터는 자유롭게 쓸 수 있지만, lexdiff의 코드는 별개의 저작물입니다.
- **코드를 옮겨 오거나 사이트를 rea로 분석해 똑같이 재구성하면 파생 저작물이 됩니다.** 햄찌법원은 Vercel에 배포된 서비스라 라이선스 위반이 됩니다. 패키지로 설치하지 않고 코드를 직접 넣어도 마찬가지입니다.
- **해결 방법은 두 가지입니다.**
  1. 친구분(라이선스 권리자)에게 "햄찌법원에서 사용 허락"을 글로 받으면 코드를 참고해 똑같이 구현할 수 있습니다.
  2. 허락 없이도, README에 적힌 기능 설명만 보고 독자적으로 구현하는 것은 문제가 없습니다.

2번이 현실적인 이유가 있습니다. 같은 분이 만든 `korean-law-mcp`(MIT 라이선스, v4.15.6)가 이미 이 프로젝트에 설치되어 있고, lexdiff 기능의 데이터 조회 함수가 대부분 그 안에 있습니다(3단 비교, 신구 대조, 연혁 법령, 해석례, 조세심판원, 관세청, 자치법규, 별표, 영향 지도). 새 패키지를 설치하지 않고 `lib/search/law-source.ts` 어댑터만 넓히면 됩니다. 그래서 허락 전까지는 rea와 lexdiff 소스 복사를 쓰지 않고 2번으로 진행하겠습니다.

## 구현 계획 (README 기능 14개 기준)

**1차 — 판례 검색 강화 (요청의 핵심)**

| README 기능 | 햄찌법원 구현 |
|---|---|
| 판례·해석례 통합 | `/search`에 탭 추가: 판례 / 법제처 해석례 / 조세심판원 재결례 / 관세청 해석 / 헌재 결정. `GET /cases?type=` 확장 |
| 약칭·구어 검색 + 즉시 조회 | "인공지능법 30조", "2023다12345" 같은 입력은 검색 목록 대신 해당 조문·판례로 바로 이동 |
| 라이브 판례 패널 | 조문 화면(`/statutes/[id]`)에 "이 조문을 인용한 판례" 패널 |
| 조회 이력 | 열람한 조문·판례를 브라우저에만 저장하고 홈과 `Ctrl+K`로 다시 열기. 로그인 동기화는 제외(DEC-016) |

**2차 — 조문 비교·시점**

| README 기능 | 햄찌법원 구현 |
|---|---|
| 타임머신 | 날짜를 고르면 그 시점 조문과 현행을 나란히 표시. 지금 "연혁에서 확인해 주세요"로 안내만 하는 `asOf`를 실제 조회로 교체(F-004 AC1) |
| 신구조문 비교 | 개정 전후 대조와 색 하이라이트, 개정 연혁에서 시점 선택 |
| 3단 위임법령 비교 | 법률 → 시행령 → 시행규칙 나란히 보기 |
| 위임법령 추적 | 조문별 행정규칙(고시·훈령) 연결 |
| 별표·별지 뷰어 | 별표 목록과 원문 링크부터. 한글 파일을 표로 그리는 것은 뒤로 미룸 |

**3차 — 자치법규·분석**

| README 기능 | 햄찌법원 구현 |
|---|---|
| 자치법규 검색 | 시도·시군구 조례·규칙 검색 |
| 조례 벤치마킹 | 지자체별 조례를 나란히 표시(AI 비교표 없음) |
| 법령 영향 추적 / 위임 미비 탐지 | 연쇄 관계 목록만 사실로 표시 |

**만들지 않는 것 (프로젝트 절대 규칙과 충돌)**

- **AI 심각도 분류(위험/검토/참고), AI 요약·비교 분석, 기준일 AI 답변, 49개 도구 에이전트 답변**: 유료 Claude 호출이 늘어나 질문당 $0.0015 상한을 넘고, 유불리 판단 금지(규칙 2)에도 걸립니다. AI 답변은 지금의 라이트 답변을 그대로 둡니다.
- **Gemini·BYOK·Google 로그인 쿼터**: DEC-004와 DEC-016에 어긋납니다.
- **질문 원문 로그 수집**: 규칙 4(개인정보)에 어긋납니다.

**공통 규칙**

- **조회 경로**: 모든 조회는 `law-source.ts` 한 곳을 거치고, 본문은 저장하지 않습니다(DEC-007).
- **표시**: 결정문도 판례처럼 요지만 보이고, `SEARCH_NOTICE`를 붙입니다.
- **한도**: IP 기준 시간당 상한(DEC-017)을 적용합니다.
- **PRD**: Phase 1 범위 밖이라 PRD 16.2에 DEC-026(제안)으로 기록하고 API.md를 갱신합니다.
- **검증**: 무료 검사(단위 테스트, 타입 검사, `pnpm build`, `docs:check`)만 합니다.
- **화면**: Figma에 없는 화면이라 기존 `/search` 스타일을 그대로 따르고, 달라지는 곳은 목록으로 보여드립니다.
