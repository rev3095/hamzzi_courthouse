## 1. 요약
자연어로 설명한 법률 문제를 구조화하고, 실제 법령·판례를 근거로 쟁점을 보여준다. 사용자가 동의하면(Phase 2) 비식별 사건 개요로 검증된 변호사의 상담 제안을 받는다.

## 2. 문제 · 가설
- **문제**: 일반인은 적용 법률·유사 판례를 찾고 해석하기 어렵고, 변호사마다 사연을 반복 설명하며, 로펌 경유 초기 상담은 비싸고 느리다.
- **가설**: AI가 사실관계·쟁점을 구조화하고 출처가 확인된 판례·법령을 연결하면 상담 준비 부담이 준다.
- **검증**: 사용자 테스트로 사건 정리 시간, 결과 유용성, 상담 준비 부담을 측정한다.

## 3. 목표 / 비목표
| 목표 | 비목표 |
|---|---|
| G1 실제 법령·판례 근거로 정보 제공 | N1 승소·형사책임·해결 가능성을 확정 판정하지 않는다 (법률 자문 아님) |
| G2 사실·쟁점·추가 확인 사항 구조화 | N2 출처가 확인되지 않은 판례·조문·사건번호를 만들지 않는다 |
| G3 명시적 동의가 있을 때만 변호사 연결 | N3 제출 문서를 확정·자동 제출하지 않는다 |
| | N4 동의 없는 공개, 미승인 계정의 사건 열람을 허용하지 않는다 |
| | N5 플랫폼이 변호사를 자동 배정하지 않는다 |

## 4. 사용자
피해자(사기·계약금), 피고소인, 분쟁 당사자(임대차·임금), 변호사(Phase 2 공급자).
**흐름**: 입력 → 구조화·개인정보 점검 → 판례·법령 근거 → (Phase 2) 요약서 확인·동의 → 비식별 게시 → 변호사 제안 → 사용자 선택·상세 제공.

## 5. 차별점 (경쟁 분석: `docs/research/02_경쟁사_비교.md`)
1. 상담 전 단계 자동화: 사건 구조화 → 근거 판례 → 사건 요약서. (로톡은 사용자가 스스로 정리해 변호사를 고른다.)
2. 역방향 연결: 개요를 올리면 변호사가 제안하고 사용자가 고른다.
3. 결과를 판정하지 않고 절차 단계별 "혼자 가능 / 전문가 권장"을 표시한다 (F-014, DEC-002).

## 6. 로드맵
| Phase | 범위 | 완료 조건 |
|---|---|---|
| 1 MVP | F-001~F-007, F-013 | 사용자가 출처를 확인하며 법률 정보를 탐색한다 |
| 2 상담 연결 | F-008~F-012, F-014 | 동의부터 변호사 응답까지 개인정보 보호가 적용된 흐름이 작동한다 |
| 3 고도화 | 시각 타임라인, 자료 관리, 고급 검색, 상담 기록 | 운영 데이터로 검증 후 추가 |

Phase 1은 **데모**를 먼저 낸다(DEC-009~013): 판례·법령 검색·본문·인용 재검증은 korean-law-mcp로 법제처를 실시간 조회하고, 결과 형식은 참고 프로토타입(질문 의도 분석 → 법령·판례 검색 → 에이전트 재검색 → 근거 기반 답변 → 두 단계 검증)과 같게 한다. 수집 DB를 검색 출처로 쓸지는 데모 뒤 다시 정한다.

Phase 2 문서는 변호사 검토용 사건 요약서로 한정한다(고소장·소장 생성·판매는 OQ-003 전 제외). 건별 과금·자동 배정은 하지 않는다(DEC-001).

### F-001 자연어 입력
- AC1 G: 메인 / W: "사기를 당했는데 어떻게 도움받을 수 있을까?" 제출 / T: F-002로 진행.
- AC2 G: 메인 / W: 빈 입력 제출 / T: 실행하지 않고 입력을 요청.
- AC3 G: 비로그인이 질문 3회 사용(이어 묻기 포함) / W: 네 번째 질문·이어 묻기 제출 / T: 소셜 로그인 요청, 로그인 후 입력을 이어서 제출 (DEC-005, DEC-010).

### F-002 구조화 + 추가 질문
- AC1 G: 입력 완료 / W: 분석 / T: 사실을 "입력된 사실 / 추론 / 확인 필요"로 나눠 보여주고 사용자가 수정 가능.
- AC2 G: 핵심 정보 누락 / W: 분석 / T: 결론 대신 추가 질문 최대 3개.
- AC3 G: 결과 표시 / W: 이어 묻기 제출 / T: 직전 질문·답변 최근 3개를 사연 맥락으로만 쓰고 근거는 다시 검색해 답한다 (DEC-011).
- 데모 범위: AC3만 구현한다. AC1의 사실 구분·수정과 AC2 추가 질문은 데모 뒤로 미룬다 (DEC-011).

### F-003 실제 판례 검색·관련성 정렬
내 상황과 관련된 실제 판례의 사실관계와 법원 판단을 확인한다.
- AC1 G: 판례 데이터 존재 / W: "계약금을 돌려받지 못했다" / T: 사건명·법원·선고일·사건번호 표시, 개인정보 미표시.
- AC2 G: 결과 없음 / W: 검색 완료 / T: "현재 검색 범위에서 찾지 못함" 안내, 판례 부재를 단정하지 않고 검색어 변경·사실 추가 안내.
- AC3 G: 결과 표시 / W: 판례 선택 / T: 검증 근거(F-005)에 실재하는 식별정보와 원문 링크만 제공, 근거에 없는 사건번호·판결 내용 생성 금지. 데모의 검증 근거는 그 요청에서 법제처로부터 가져온 자료다 (DEC-009).

### F-004 법령·조문·시행일
- AC1 G: 판례 표시 / W: 상세 열람 / T: 판결 인용 법령과 "관련될 수 있는 법령"을 구분하고, 판결 당시와 현행 시행일을 함께 표시.

### F-005 인용 출처 검증
- AC1 G: AI 응답 생성 / W: 사건번호·조문 포함 / T: DB와 대조해 불일치는 제거하거나 "미확인" 표시, 실패율 기록.
- AC2 (데모, DEC-009) G: 답변 문단마다 출처·인용 구절 / W: 렌더링 전 / T: ① 출처가 그 요청에서 가져온 자료인지 ② 인용 구절이 원문에 글자 그대로 있는지 ③ 본문의 조문·사건번호를 korean-law-mcp `verify_citations`로 법제처에 재조회해 실존하는지 확인. ①·③ 실패 항목은 출력하지 않고, ②만 실패하면 "확인 필요"로 표시. 실패율 기록.

### F-006 결과 없음·정보 부족
- AC1 G: 유사도 임계값 미만 / W: 검색 완료 / T: 관련 조항과 일반 경로를 **"AI 추천(판례 근거 아님)"** 라벨로 제공.
- AC2 G: 외부 오류 / W: 검색 / T: 검색 실패와 결과 없음을 구분해 안내, 재시도 제공.

### F-007 개인정보 경고·비식별화
- AC1 G: 이름·전화·주민번호·계좌 패턴 / W: 제출 / T: 경고·마스킹, 원문은 로그·프롬프트·DB에 남기지 않음 (DEC-006).
- AC2 G: 민감정보(건강·범죄경력) 가능성 / W: 첫 입력 / T: 별도 동의.

### F-008 상담 준비 에이전트 + 사건 요약서
- AC1 G: 해결 방향 제안 / W: 사용자 비동의 / T: 이유를 묻고 수정안 재제시.
- AC2 G: 사용자 동의 / W: 확정 / T: 사실·쟁점·희망 업무·근거 판례 요약서 생성, "제출용 아님" 표시.

### F-009 최종 확인·동의
- AC1 G: 요약서 생성 / W: 게시 요청 / T: 내용과 공개 범위("상세는 선택한 변호사만")를 보여주고 확인받음.
- AC2 G: 동의 미완료 / W: 게시 요청 / T: 게시하지 않고 확인 사항 안내.
- AC3 동의 기록(대상·목적·항목·기간·철회 방법) 저장.

### F-010 변호사 자격·계정 승인 `[게이트]`
- AC1 미검증 계정은 게시판 접근 불가. AC2 승인 이력 기록, 상태 변경 시 권한 즉시 갱신. AC3 승인 계정도 허용 범위 밖 열람 불가.

### F-011 비식별 사건 개요 게시 `[게이트]`
- AC1 G: F-009 동의 완료 / W: 게시 / T: 공개 승인 항목만 등록.
- AC2 G: 간접 식별 위험(희귀 지명·직장명) / W: 게시 전 점검 / T: 수정 요청.

### F-012 상담 제안·선택·상태 `[게이트]`
- AC1 G: 승인 변호사 열람 / W: 제안 / T: 프로필·공개 단가 표시, 플랫폼은 배정하지 않음.
- AC2 G: 사용자 선택 / W: 상세 제공 요청 / T: 그 변호사에게만 허용 항목 제공, 접근 기록.
- AC3 상태: 게시됨 → 제안 받음 → 선택됨 → 상담 진행 → 종료. "선임 완료"로 표시하지 않음.

### F-013 기능 게이트
상태값 `Pending Review / Conditional / Approved / Excluded`. 대상: F-010~F-012, 과금, 법률문서 생성.
- AC1 G: Pending Review / W: 활성화 시도 / T: 차단, 미완료 항목 표시.
- AC2 G: Conditional / W: 활성화 시도 / T: 조건 해결·재승인 기록 전 차단.
- AC3 G: Approved / W: 실행 / T: 승인 범위 안에서만 동작.

### F-014 절차 단계별 안내
- AC1 G: 사건 유형 확정 / W: 결과 표시 / T: 단계별 예상 기간과 "혼자 가능 / 상황에 따라 / 전문가 권장" 라벨, 기간·비용은 계산 함수·공식 기준만 사용하고 출처 표시.
- AC2 "전문가 권장" 단계에 "변호사와 상담하기"(F-008) 진입점.

## 8. AI 요구사항
### 8.1 한다 / 하지 않는다
| 한다 | 하지 않는다 |
|---|---|
| 사실·유형·쟁점 추출, 추가 질문 | 출처 없는 판례·조문·사건번호 생성 |
| DB 판례·법령 검색, 판결 요지·인용 법령 요약 | 유사 판례로 동일 결과 단정, 승소·유죄 확정 |
| 판례와 사용자 사실의 공통점·차이 구분, 한계 표시 | 미확인 사실을 확인된 것처럼 제시, 동의 없는 전달 |

### 8.2 파이프라인
입력 → PII 점검(F-007) → LLM 구조화(F-002) → 판례·법령 검색 → 메타데이터 검증 → 근거 기반 요약 → 인용 대조(F-005) → 실패 항목 제거·불확실성 표시.
- **모델**: 메인 `claude-opus-5-5`, 분류·추출 `claude-haiku-5-5` (PoC로 확정). LLM에는 마스킹본만 보낸다.
- **검색**: 키워드 색인으로 시작하고, 벡터 검색은 임베딩 모델 확정(OQ-ARC-03) 후 추가한다.
- **가드레일(코드)**: DB에 없는 사건번호는 렌더링 차단. 숫자는 계산 함수 결과만.
- **데모 파이프라인 (DEC-009, DEC-011)**: 입력 → PII 점검 → 질문 의도 분석(분야·알고 싶은 것·관련 법률·검색어, Haiku) → 관련 법령 조문 검색 + 판례 검색(korean-law-mcp, 동시) → 에이전트 재검색(법령·판례 도구, 최대 3라운드) → 근거 자료 안에서만 답변(문단별 출처·원문 구절, Opus) → 두 단계 검증(F-005 AC2) → 제공. 검색어도 마스킹본에서 만든다. 기간 숫자는 조문·판례 원문 구절 안에 있을 때만 쓴다.

### 8.3 출력 구조·표현
**구조**: 사건 요약 → 확인된 사실/미확인 → 쟁점 → 관련 판례(사건명·법원·선고일·사건번호·원문 링크) → 판례의 실제 판단 → 관련 법령(판결 인용 vs 잠재 관련) → 사용자 상황과의 차이 → 추가 확인 사항 → 다음 단계.
**데모 구조 (DEC-011)**: 분야·알고 싶은 것·관련 법률 → 답변(문단별 출처·원문 구절) / 법령 / 판례 / 검증 탭 → AI가 더 찾아본 과정 → 이어 묻기.
**표현**: "반드시 승소", "무조건 처벌", "100%" 금지 · 판례 내용과 AI 설명 구분 · 유사도를 승소 가능성으로 표시하지 않음 · 모든 결과에 "AI 생성 · 법률 자문 아님".

### 8.4 출시 기준 (DEC-003)
| 지표 | 기준 |
|---|---|
| 허위 판례·조문 인용 | 0건 |
| 핵심 인용의 공식 출처 연결률 | ≥ 95% |
| 정답 판례 Top-5 포함률 | ≥ 70% |
| 판결 요지 요약 정확도(전문가) | ≥ 90% |
| 사실 왜곡·임의 추가 / 확정 표현 / PII 노출 | 각 0건 |

평가셋은 사건 유형별 질의 + 전문가 검수 정답(OQ-005, OQ-007). PII 노출·출처 검증 실패 시 출시 보류.

## 9. 데이터
### 9.1 소스 (상세: `docs/research/01_데이터_소스.md`)
| 소스 | 용도 | 상태 |
|---|---|---|
| 국가법령정보 공동활용 Open API (OC 인증키 `OPEN_LAW_API_KEY`, JSON) | 판례 목록·본문, 현행법령, 법령용어, 지식베이스 | **사용 중** — 판례·현행법령 실호출 확인 |
| korean-law-mcp 4.15.6 (MIT, 같은 Open API의 래퍼) | 데모의 판례 검색·본문, 법령 조문, 인용 재조회 — 서버 코드에서 라이브러리로 직접 호출 | **데모 런타임** (DEC-009) |
| 대법원 판결서 인터넷 열람 | 원문 링크 안내 | 수집하지 않음 |
| 사용자 입력 | 사건 정보 | 9.2 적용 |

- 판례는 메타데이터·판시사항·판결요지·참조조문·원문 링크만 저장한다. 전문은 저장하지 않는다(DEC-007).
- 데모에서 실시간 조회한 판례 본문은 요청 메모리 안에서만 쓰고, 저장은 메타데이터와 60자 이내 인용 구절로 한정한다(DEC-007, DEC-009).
- 법제처 API는 등록된 IP에서만 호출되므로 데모 웹 서버도 등록 가능한 실행 환경이어야 한다(OQ-ARC-05).
- 본문을 JSON으로 주지 않는 국세법령정보시스템 출처 판례는 제외한다(DEC-008).
- 형사 미확정·소액사건 판결은 공개 범위 밖이라 검색 한계를 화면에 안내한다.
- 법제처 API는 등록된 IP에서만 호출되므로 수집기는 고정 IP 환경에서 실행한다(OQ-ARC-05).

### 9.2 개인정보
- 최소 수집, 입력 원문 미저장·마스킹본만 저장(DEC-006).
- 사건 원본 / 공개 개요 / 변호사 제공본 분리. 사용자는 본인 것만, 변호사는 허용 범위만, 관리자는 최소 인원 + 접근 로그.
- 제공 동의 고지: 받는 자·목적·항목·보유 기간·거부 가능 여부. LLM·클라우드 처리위탁·국외이전 요건 검토.
- 항목별 보유 기간 정의, 백업·로그 포함 파기, 삭제 요청 절차.

### 9.3 갱신·품질
증분 수집·실패 기록, 법령 시행일·버전 관리, 사건번호·선고일·법원 누락 검사, 비식별 재검사(`flagged`는 검색 제외).

## 10. 규제·법무 (근거: `docs/research/03_규제_쟁점.md`)
법률 검토가 끝나지 않은 기능은 출시하지 않는다(F-013).

| 영역 | 핵심 쟁점 |
|---|---|
| 변호사 정보·광고 | 광고와 소개·알선 구분 |
| 사건 게시·매칭 | 변호사법 제34조(알선 대가), 플랫폼 관여 수준 |
| AI 법률문서 | 변호사법 제109조(비변호사 법률사무), 법무사법 |
| 개인정보 | 민감정보 별도 동의, 제3자 제공 |
| AI 투명성 | AI 기본법(2026.1.22 시행) 생성형 AI 고지 |

**수익모델 후보(전부 Pending Review)**: A 변호사 광고·정액 구독(중간) · B 변호사용 도구 구독(낮음~중간) · C 건별 과금(높음) · D 수임 성사 수수료(매우 높음) · E AI 법률문서 판매(높음).
**검토 완료 전 금지**: 성사 연동 수수료·건별 과금, 개별 사건 문서 판매·자동 제출, 미검증 계정의 사건 접근, 동의·비식별 절차 없는 게시.
**고지**: "햄찌법원은 생성형 AI로 법령·판례를 검색·요약하는 정보 서비스이며 법률 자문을 대체하지 않습니다. 햄찌 판사는 AI 캐릭터입니다." 기한 임박 사건은 전문가 상담을 우선 안내한다.

## 12. UX
첫 화면은 질문창 하나 · 용어는 쉬운 설명과 함께 · 요약과 원문 구분 · 결과를 꾸며내지 않음 · 확인하지 않은 AI 내용은 확정 등록하지 않음. 디자인: 캔버스 "D+ 햄찌법원" 시안, `docs/05_브랜드_가이드.md`.
**Phase 1 흐름**: 입력 → (추가 질문) → 사실 요약 확인·수정 → 판례·법령 결과 → 원문 확인 → 부족하면 한계 안내.
**데모 흐름 (DEC-011~013)**: 홈(질문창 + 분야별 예시 질문 피드) → 개인정보 확인 → 진행 단계 실시간 표시 → 결과 탭 → 이어 묻기. 피드는 직접 작성한 가상 사연이며 "예시 질문"으로 표시한다(다른 플랫폼 이용자 글을 옮기지 않음, DEC-012).
