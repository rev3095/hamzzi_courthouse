## 1. 요약 & 비전
- **요약**: 자연어로 설명한 법률 문제를 구조화하고, 실제 법령·판례를 검색해 근거와 쟁점을 제공한다. 사용자가 동의하면 비식별 사건 개요로 검증된 변호사의 상담 제안을 받을 수 있는 AI 법률 정보 탐색·상담 연결 플랫폼.
- **비전**: 법률 용어를 몰라도 내 문제를 이해하고, 근거를 보고 다음 선택지를 고르며, 필요할 때 적절한 변호사에게 효율적으로 상담을 요청한다.

## 2. 문제 정의
| 구분 | 내용 |
|---|---|
| 페인 포인트 | 적용 법률·유사 판례를 찾고 해석하기 어렵다. 변호사마다 같은 사연을 반복 설명해야 하고, 로펌 경유 초기 상담은 비싸고 느리다. |
| 해결 가설 | AI가 사실관계·쟁점을 구조화하고 출처가 확인된 법령·판례를 연결하면 상담 준비 부담이 준다. |
| 차별화 가설 | 사용자가 확인한 사건 요약서 하나로 여러 변호사의 상담 제안을 받으면 탐색 비용이 준다. |
| 검증 | 사용자 인터뷰·프로토타입 테스트로 ① 사건 정리 시간 ② 검색 결과 유용성 ③ 상담 준비 부담 감소를 측정. |

## 3. 목표 / 비목표
| 목표 | 비목표 |
|---|---|
| G1 실제 법령·판례 검색으로 근거 있는 정보 제공 | N1 승소 가능성·형사책임·해결 가능성을 확정 판정하지 않는다 (= 법률 자문을 하지 않는다) |
| G2 사실관계·쟁점·추가 확인 사항 구조화 | N2 출처가 확인되지 않은 판례·조문·사건번호를 생성하지 않는다 |
| G3 명시적 동의가 있을 때만 변호사 연결 진행 | N3 변호사 검토 없이 법원·수사기관 제출 문서를 확정하거나 자동 제출하지 않는다 |
| | N4 동의 없는 정보 공개, 미승인(비변호사) 계정의 사건 열람을 허용하지 않는다 |
| | N5 플랫폼이 변호사를 자동 배정하지 않는다 |

## 4. 사용자 & 시나리오
| 페르소나 | 상황 | 원하는 것 |
|---|---|---|
| 피해자 | 중고거래 사기, 계약금 미반환 | 어떤 법으로 대응하는지, 무엇을 준비할지 |
| 피고소인 | 고소장을 받음 | 혐의 관련 법조항과 비슷한 판례 |
| 분쟁 당사자 | 임대차·임금 분쟁 | 절차와 변호사 필요 여부 |
| 변호사(공급자) | 신규 상담 유입 필요 | 정리된 사건 개요를 보고 상담 제안 |

**핵심 흐름 (JTBD)**: ① 사건 입력 → ② AI 구조화·비식별 점검 → ③ 판례·법령 근거 확인 → ④ (선택) 사건 요약서 확인·동의 → ⑤ 비식별 개요 게시 → ⑥ 변호사 상담 제안 → ⑦ 사용자가 변호사 선택 후 별도 동의로 상세 정보 제공.

## 5. 경쟁·차별점
| 서비스 | 구조 | 한계(우리 기회) |
|---|---|---|
| 로톡 | 변호사 정액 광고비. 사용자가 변호사를 검색해 15분 전화·영상·방문 상담 예약. 헌재 2022 변협 광고규정 일부 위헌, 법무부 2023 징계 취소 | 사용자가 문제를 스스로 정리해 변호사를 골라야 함. 상담 전 정보 단계가 약함 |
| 엘박스·빅케이스·케이스노트 | 판례 검색(주로 전문가용 구독) | 일반인 언어·절차 안내 없음 |
| 어니언 | 법률사무소의 소장 첨삭(유료) | 정보 탐색·연결 없음 |

**차별점**
1. 상담 전 단계 자동화: 사건 구조화 → 근거 판례 → 사건 요약서.
2. 역방향 연결: 사건 개요를 올리면 변호사가 제안하고, 사용자가 비교해 선택.
3. 직관적 진행 안내: 결과를 "판정"하지 않고 **절차 단계별로 "혼자 진행 가능 / 전문가 권장"** 을 표시 (F-014). N1과 충돌하지 않도록 승패·가능성이 아니라 절차 난이도로 표현한다.

- 사건별 과금·자동 배정은 별도 승인 없이 활성화하지 않는다 (DEC-001).

| F-003 | 실제 판례 검색·관련성 정렬 | P0 | 1 |
| F-004 | 관련 법령·조문·시행일 표시 | P0 | 1 |

수용 기준은 `G(Given) / W(When) / T(Then)` 로 표기한다.

### F-001 자연어 입력
일상어 또는 키워드("계약금 반환")로 문제를 입력한다.
- AC1 G: 메인 화면 / W: "사기를 당했는데 어떻게 도움받을 수 있을까?" 입력·제출 / T: F-002로 진행.
- AC2 G: 메인 화면 / W: 빈 입력으로 제출 / T: 실행하지 않고 입력을 요청한다.
- AC3 G: 비로그인 사용자가 이미 질문 1회를 사용함 / W: 두 번째 질문(추가 질문 답변 포함) 제출 / T: 소셜 로그인(Google 등)을 요청하고, 로그인 후 작성 중인 입력을 이어서 제출할 수 있다 (DEC-005).

### F-002 구조화 + 추가 질문
사건 유형, 당사자 관계, 시간 순서, 쟁점, 검색 질의를 추출하고 부족한 정보를 질문한다.
- AC1 G: 입력 완료 / W: 분석 / T: 사실관계 요약을 "입력된 사실 / 추론 / 확인 필요"로 구분해 표시하고 사용자가 수정할 수 있다.
- AC2 G: 핵심 정보 누락 / W: 분석 / T: 결론 대신 추가 질문을 최대 3개 제시한다.

### F-003 실제 판례 검색·관련성 정렬
입력을 검색 질의로 바꿔 판례 DB를 조회하고, 관련성 순으로 정렬해 원문 출처를 제공한다.
**사용자 스토리**: 내 상황과 관련된 실제 판례의 사실관계와 법원 판단을 확인하고 싶다.
- AC1 G: 판례 데이터 존재 / W: "계약금을 돌려받지 못했다" 입력 / T: 사건명·법원·선고일·사건번호를 표시하고, 당사자 이름·주민번호 등 개인정보는 표시하지 않는다.
- AC2 G: 대응 결과 없음 / W: 검색 완료 / T: "현재 검색 범위에서 찾지 못함"을 알리고 판례 부재를 단정하지 않으며, 검색어 변경·사실 추가를 안내한다.
- AC3 G: 결과 표시 중 / W: 판례 선택 / T: DB에 실재하는 사건 식별정보와 원문 출처를 제공한다. DB에 없는 사건번호·판결 내용은 생성하지 않는다.
- 완료 조건: AC1~3 자동 테스트 통과 + 출처 연결 검증(F-005) 통과.

### F-004 법령·조문·시행일
- AC1 G: 판례 표시 / W: 상세 열람 / T: 판결문 인용 법령과 "사용자 상황에 관련될 수 있는 법령"을 구분하고, 판결 당시 법령과 현행 법령의 시행일을 함께 표시한다.

### F-005 인용 출처 검증
- AC1 G: AI 응답 생성 / W: 응답에 사건번호·조문 포함 / T: 검색 결과와 대조해 불일치 항목을 제거하거나 "미확인"으로 표시한다. 검증 실패율을 로그에 남긴다.

### F-006 결과 없음·정보 부족
- AC1 G: 유사도가 임계값 미만 / W: 검색 완료 / T: 유사 판례 대신 "관련 법 조항과 일반 해결 경로"를 **AI 추천(판례 근거 아님)** 라벨로 제공한다.
- AC2 G: 외부 API 오류 / W: 검색 / T: 검색 실패와 결과 없음을 구분해 안내하고 재시도를 제공한다.

### F-007 개인정보 경고·비식별화
- AC1 G: 입력에 이름·전화·주민번호·계좌번호 패턴 / W: 제출 / T: 경고 후 마스킹 옵션을 제공하고, 원문을 로그·프롬프트 기록에 저장하지 않는다.
- AC2 G: 민감정보(건강·범죄경력 등) 입력 가능성 / W: 첫 입력 / T: 별도 동의를 받는다.

### F-008 상담 준비 에이전트 + 사건 요약서
"변호사와 상담하기" 선택 시 에이전트가 해결 방향(예: 형사 고소 / 민사 배상)을 제안하고, 사용자가 동의·비동의로 다듬는다.
- AC1 G: 방향 제안 / W: 사용자 비동의 / T: 이유를 묻고 수정안을 다시 제시한다.
- AC2 G: 사용자 동의 / W: 확정 / T: 사실관계·쟁점·희망 업무·근거 판례가 담긴 사건 요약서를 생성한다. 법원 제출용 문서가 아니라고 표시한다.

### F-009 최종 확인·동의
- AC1 G: 요약서 생성 / W: 게시 요청 / T: "이 내용이 맞나요?", "공개 항목은 ○○, 상세 정보는 선택한 변호사만 봅니다"를 보여주고 확인을 받는다.
- AC2 G: 동의 미완료 / W: 게시 요청 / T: 게시하지 않고 필요한 확인 사항을 안내한다.
- AC3 동의 기록(대상·목적·항목·기간·철회 방법)을 저장한다.

### F-010 변호사 자격·계정 승인 `[게이트]`
- AC1 자격 검증 미완료 계정은 사건 게시판에 접근할 수 없다.
- AC2 승인 이력을 기록하고, 상태가 바뀌면 권한을 즉시 갱신한다.
- AC3 승인 계정도 허용 범위를 넘는 개인정보를 열람할 수 없다.

### F-011 비식별 사건 개요 게시 `[게이트]`
- AC1 G: F-009 동의 완료 / W: 게시 / T: 공개 승인된 개요만 등록하고 원본·비공개 항목은 노출하지 않는다.
- AC2 G: 개요에 간접 식별 위험(희귀 지명·직장명 등) / W: 게시 전 점검 / T: 수정을 요청한다.

### F-012 상담 제안·선택·상태 `[게이트]`
- AC1 G: 승인 변호사가 개요 열람 / W: 상담 제안 / T: 사용자에게 제안(변호사 프로필·공개 단가)을 표시한다. 플랫폼은 배정하지 않는다.
- AC2 G: 사용자가 변호사 선택 / W: 상세 정보 제공 요청 / T: 해당 변호사에게만 허용 항목을 제공하고 접근 기록을 남긴다.
- AC3 상태: 게시됨 → 제안 받음 → 선택됨 → 상담 진행 → 종료. 게시나 선택만으로 "선임 완료"로 표시하지 않는다.

### F-013 법률 검토 상태 기반 기능 게이트
상태값: `Pending Review / Conditional / Approved / Excluded`. 대상: F-010~F-012, 모든 과금, 법률문서 생성.
- AC1 G: Pending Review / W: 운영자가 활성화 시도 / T: 차단하고 미완료 검토 항목을 표시한다.
- AC2 G: Conditional / W: 활성화 시도 / T: 조건 해결과 재승인 기록 전까지 차단한다.
- AC3 G: Approved / W: 실행 / T: 승인 범위 안에서만 동작한다.

### F-014 절차 단계별 안내
- AC1 G: 사건 유형 확정 / W: 결과 표시 / T: 절차 단계별 예상 기간과 "혼자 진행 가능 / 상황에 따라 / 전문가 권장" 라벨을 표시한다. 기간·비용은 계산 함수나 공식 기준 결과만 쓰고 출처를 단다.
- AC2 "전문가 권장" 단계에서 "변호사와 상담하기"(F-008) 진입점을 보여준다.

## 8. AI 요구사항
### 8.1 한다 / 하지 않는다
| 한다 | 하지 않는다 |
|---|---|
| 사실관계·유형·당사자·시간순서·쟁점 추출, 추가 질문 | 출처 없는 판례·조문·사건번호·판결 결과 생성 |
| 공식 데이터에서 법령·판례 검색, 판결 요지·인용 법령 요약 | 유사 판례를 근거로 동일 결과 단정 |
| 판례와 사용자 사실의 공통점·차이 구분 | 형사책임·유죄·승소·해결 가능성 확정 |
| 미확인 사실·한계 표시 | 미확인 사실을 확인된 것처럼 제시 |
| (Phase 2) 사용자 확인을 거친 사건 요약서 작성 | 동의 없는 전달·게시, 제출 문서 타당성 보장·자동 제출 |

### 8.2 파이프라인·RAG
1. 입력 → 2. PII 점검(F-007) → 3. LLM 구조화(F-002) → 4. 법령·판례 하이브리드 검색(키워드+벡터) → 5. 메타데이터 검증(사건번호·시행일·원문 링크) → 6. 근거 기반 요약 → 7. 인용 대조(F-005) → 8. 실패 항목 제거·불확실성 표시.

- **LLM 후보**: 메인 `claude-opus-5-5`, 분류·추출 `claude-haiku-5-5`. PoC에서 한국어 법률 질의 성능·비용·지연·데이터 보호 조건을 비교해 확정.
- **RAG 원칙**: 핵심 주장은 출처에 연결 / 키워드 일치만으로 관련성 판단 금지 / 사실관계·쟁점·판단·적용 시점 구분 / 판결 당시 법령과 현행 법령 구분 / 미검색은 "범위 내 미확인"으로 안내.
- **가드레일(코드)**: DB에 없는 사건번호는 렌더링 단계에서 차단. 기간·비용 숫자는 계산 함수 결과만 사용.

### 8.3 출력 구조와 표현
**응답 구조**: 사건 요약 → 확인된 사실/미확인 정보 → 쟁점 → 관련 판례(사건명·법원·선고일·사건번호·원문 링크) → 판례의 실제 판단 → 관련 법령(판결 인용 vs 잠재 관련) → 사용자 상황과의 차이 → 추가 확인 사항 → 다음 단계(공공기관·변호사 상담 등).

**표현 규칙**
- 금지: "반드시 승소", "무조건 처벌", "100% 해결" 등 확정 표현.
- 판례에서 직접 확인한 내용과 AI가 연결해 설명한 내용을 구분한다.
- 유사도 점수를 승소 가능성으로 표시하지 않는다.
- 모든 결과에 "AI 생성 · 법률 자문 아님"을 표시한다.

### 8.4 평가와 출시 게이트
평가셋은 사건 유형별 질의 + 전문가 검수 정답으로 개발 초기에 구축한다. 아래 수치를 출시 기준으로 채택한다(DEC-003). 전문가 검토에서 조정되면 결정 로그에 기록한다.

| 지표 | 출시 기준 |
|---|---|
| 허위 판례·조문 인용 | 0건 |
| 핵심 인용의 공식 출처 연결률 | ≥ 95% |
| 정답 판례 Top-5 포함률 | ≥ 70% |
| 판결 요지 요약 정확도(전문가 평가) | ≥ 90% |
| 사실관계 왜곡·임의 추가 | 0건(샘플 기준) |
| 확정 표현 | 0건 |
| 출력·로그 PII 노출 | 0건 |

중대 결함(PII 노출, 출처 검증 실패) 발견 시 출시를 보류한다.

### 9.2 개인정보
- **최소 수집**: 주민번호·계좌·주소·제3자 연락처 입력을 막고 안내한다(F-007). 첨부 기능은 접근 통제 준비 후 도입.
- **입력 원문 미저장**: 입력 원문은 저장하지 않고 마스킹본만 저장한다. 원문 저장이 필요해지면 별도 결정·동의·마이그레이션을 거친다 (DEC-006).
- **분리 저장**: 사건 원본 / 비식별 공개 개요 / 변호사 제공본을 분리한다.
- **접근**: 사용자는 본인 것만, 승인 변호사는 허용 범위만, 관리자는 최소 인원 + 접근 로그.
- **제공 동의 고지**: 받는 자·목적·항목·보유 기간·거부 가능 여부.
- **외부 처리**: LLM·클라우드 제공업체에 대한 처리위탁·국외이전 요건 검토.
- **보유·파기**: 항목별 보유 기간 정의, 백업·로그 포함 파기, 삭제 요청 절차 제공.

### 9.3 갱신·품질
- 법령 개정·시행일 추적, 판례 원본 갱신 주기 점검.
- 수집 실패·원문 링크 끊김 감지 → 기록·복구.
- 사건번호·선고일·법원·법령명 누락·불일치 검사.

### 10.4 검토 완료 전 금지
- 수임 성사 연동 수수료, 사건별 과금 결제 흐름
- AI 생성 개별 사건 문서의 제출용 판매·자동 제출
- 자격 미확인 계정의 사건 정보 접근
- 비식별·접근권한·동의 절차 없는 사건 게시

### 10.5 사용자 고지
"햄찌법원은 생성형 AI로 법령·판례를 검색·요약하는 정보 서비스입니다. 개별 사건의 법률 판단이나 변호사 자문을 대체하지 않습니다. 햄찌 판사는 AI 캐릭터입니다." 고지문만으로 의무가 없어지지 않으므로 기능 자체가 원칙을 따르도록 설계한다. 기한이 임박한 사건(공소시효·제소기간 등)은 전문가 상담을 우선 안내한다.

### 10.6 검토 완료 기준
A~E 영역별 검토 기록, 수익모델별 허용 여부·조건, 문서 유형별 제공 범위, 개인정보 수집·공개·제공·보유·삭제 정책, 조건부 사항 테스트 완료, 미승인 기능 비활성 확인.
