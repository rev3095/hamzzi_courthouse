# 복잡한 사연 예시 — 쪽별 답변·문서 작성 절차 (DEC-059, 2026-11-25)

예시 질문(lib/demo/examples.json) 45개 가운데 함정 2개(`trap-number`·`trap-vague`)를 뺀 43개를 다시 만들었다.
화면에는 지금처럼 **짧은 요약 질문**이 보이고, 답변은 **600~1,400자의 자세한 상황**으로 만든다.
같은 사건을 쪽별로 나눠, 쪽마다 답변과 **문서 작성 절차·초안**을 붙였다.

## 과정

| 단계                   | 스크립트                                                                                                          | 모델·호출                                                                                  | 결과                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| 1. 사연 쓰기           | `scripts/gen-complex-scenarios.mjs`                                                                               | Opus 5.5 effort high, 예시마다 1회                                                         | `scenarios/<id>.json` — 쪽마다 요약 질문·자세한 상황·쓸 문서                            |
| 2. 질문 펼치기         | `scripts/build-complex-questions.mjs`                                                                             | 없음                                                                                       | `questions.json` — 쪽 1개 = 질문 1건 (73건)                                             |
| 3. 답변                | `scripts/gen-server.mjs`로 띄운 관리자 모드 로컬 서버 + `GEN_DIR=evals/examples-complex scripts/gen-examples.mjs` | Pro Max DeepSearch(구조화 Haiku → 쟁점별 법제처 검색 → Opus 5.5 high 답변 1회 → 인용 검증) | `out/<id>--<쪽>.json`                                                                   |
| 4. 문서 작성 절차·초안 | `scripts/gen-complex-docs.mjs`                                                                                    | Opus 5.5 effort high, 쪽마다 1회                                                           | `docs/<id>--<쪽>.json` — 절차 단계(혼자 가능·전문가 권장), 문서 초안, 제출 전 확인 목록 |
| 5. 반영                | `python -X utf8 scripts/merge_complex_examples.py`                                                                | 없음                                                                                       | `lib/demo/examples.json`의 `sides`                                                      |

쪽 나누기:

- 민사: 원고(청구하는 쪽)·피고(청구받는 쪽)
- 형사: 고소인(피해자)·피의자
- 한쪽만: 상대가 행정청이거나 신청만 하는 절차(행정 처분·과태료·세금·실업급여·영업신고·등기·의가사 제대·개인회생·상속), 피해자 보호가 중심인 사건(성범죄·가정폭력·스토킹·군 가혹행위) — 13개

## 거르기 (규칙)

- 사연: 사람은 역할로만, 이름·연락처·주소·계좌·사건번호 없음. 기한·비용 숫자는 쓰지 않는다(사실관계 숫자만).
- 답변: 법제처 재조회와 원문 대조를 통과한 문단(`check: "verified"`)만 넣는다. 2개 미만인 쪽은 넣지 않는다.
- 문서 작성 절차·초안: 저장 전(`gen-complex-docs.mjs`)과 반영 때(`merge_complex_examples.py`) 두 번 거른다.
  - 조문·판례: 그 쪽에서 검증된 근거만 쓸 수 있다. 조문은 법령 이름까지 맞춘다(정식 이름·약칭 표·'같은 법' 이어받기).
  - 숫자: 단위가 붙은 숫자(일·주·개월·년·원·% 등)와 한글 수사는 상황 글이나 검증된 인용 구절에 같은 꼴이 있어야 한다 — 기한·비용을 모델이 만들지 않게(절대 규칙 3).
  - 결과 단정 표현(`isAssertive`)이 든 문장은 뺀다(절대 규칙 2).
- 화면: `AI_NOTICE`(답변·자세한 상황·문서 절차), `DRAFT_NOTICE`, `CHECK_NOTICE`. 머리 안내는 `EXAMPLE_SIDES_NOTE`("AI가 지어낸 가상 사연").

## 생성 중 찾아 고친 것

- 긴 사연에서 DeepSearch 쟁점 제목이 40자를 넘어 모두 버려지고 일반 답변으로 내려갔다 → 상한 60자(`ISSUE_TITLE_MAX`), 지시문은 30자 이내.
- 여러 질문을 동시에 보내면 익명 세션 쿠키가 서로 덮어써 분석 요청이 403이 났다 → `gen-examples.mjs`가 실행 줄마다 쿠키를 따로 둔다.
- 사기 예시 고소인 쪽은 첫 답변에서 검증 문단이 1개뿐이라 다시 만들었다.

## 예 — `lease-01`

- 원고 쪽 · 임차인: "전세 계약이 끝났는데 집주인이 새 세입자가 들어와야 보증금을 준다며 2억 5천만 원을 돌려주지 않아요. 임차권등기를 하고 이사했는데, 이제 소송을 하려면 어떻게 해야 하나요?"
  - 자세한 상황 1,092자(갱신 거절 메시지 시점, 내용증명·임차권등기·이사, 원상복구비 공제 주장)
  - 답변 문단: 주택임대차보호법 제6조, 제6조의2
  - 문서 작성 절차 8단계 → 소장(임대차보증금반환 청구) 초안
- 피고 쪽 · 임대인: "전세 세입자가 계약이 끝났다며 보증금 2억 5천만 원 반환 소송을 걸었어요. 새 세입자를 못 구해 돈이 없는데, 답변서는 어떻게 써야 하나요?"
  - 자세한 상황 1,102자 → 문서 작성 절차 7단계 → 답변서 초안
